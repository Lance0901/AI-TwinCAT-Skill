# testing: Read before writing PLC variables or running tests (WriteVariable, NewTestCase, RunTest, RunTestCycle).

## Steps
1. `NewTestCase`: Setup / Teardown = arrays of `{Path, Value}` writes, Assertions on symbol paths.
2. PLC already running: `RunTest`. Full cycle (build, activate, login, run, stop): `RunTestCycle` with the test cases.
3. Single values: `ConnectAds` -> `WriteVariable` / `ReadVariable` / `WatchVariable`.

`WriteVariable`, `RunTest` and `RunTestCycle` change the running PLC: on a target that is not `local-umrt` the tool asks the user in a confirmation form first (GetGuide('consent')). Use the condition-based waits of `NewTestCase`, not the deprecated `WaitMs`.

## When it fails
- A failed assertion is a test result: report it, do not change the test to pass.
- `LIFECYCLE_BLOCKED`, `RUNTIME_CRASHED`, `SYSTEM_EXCEPTION`: GetGuide('recovery').
- `TYPE_MISMATCH`: write STRUCT / ARRAY members one by one.

## Tool reference
Full behaviour of the tools of this topic (their descriptions keep the short form).

### RunTestCycle
Builds, activates (TwinCAT restart) and runs the PLC: changes the running machine. Full automated test cycle: build (unless SkipBuild), activate configuration, login, run every test case from NewTestCase, then stop the PLC (unless KeepRunning). Returns per-test results. Can take many minutes (timeout 900 s). A test case that waits with the deprecated WaitMs has data.warning in its result; the report lists them in data.warnings. RUNTIME_CRASHED during activation is returned as it is (data.runtimeCrash). Fail closed: success=true only after the readback reached the requested state. While the target has a lifecycle block (recorded when SetSystemState / EnableConfig / SetPlcState sent a runtime-changing request and then failed: data.lifecycleBlock) this tool returns LIFECYCLE_BLOCKED and does nothing: stop, report data.lifecycleBlock to the user, do not switch to another control channel (raw ADS, COM, DTE, GUI, console), and call ClearLifecycleBlock only after the user agreed. Consent (MCP server): through the TcAuto MCP server that question is asked by the server itself: when the target AmsNetId is not local-umrt (targetKind; unknown included), the first such call of this server session to that target makes the server ask the user in a confirmation form (MCP elicitation) before anything runs; local-umrt never asks. The AI cannot answer the form and a chat answer does not replace it. Refused: CONSENT_DECLINED (the user did not approve) or CONSENT_REQUIRED (the client cannot show confirmation forms, the form failed or timed out); nothing ran: stop and report, do not retry or work around it. The PowerShell module itself does not ask.

### WriteVariable
Write a single PLC variable by symbol path via ADS. Writes directly into the running PLC; may drive outputs or axes. Value is converted to the PLC type of the symbol: JSON bool for BOOL, number for integer/REAL types, string for STRING; TIME/TOD take an IEC literal ("Ts", "Tm30s500ms", "TOD:30:00"; integer ms also accepted), LTIME/LTOD "LTIMEus" (or integer ns), DATE/DT "D-10-20" / "DT-10-20-12:30:00" / ISO 8601 (or integer seconds since 1970), enums an integer or the member name. STRUCT/ARRAY cannot be written as a whole (TYPE_MISMATCH): write their members. data.written is the value actually written: the normalized literal for time types ("Tms" -> "Ts", raw integer in ms/ns/unix), the converted number otherwise, plus name for enums. Requires ConnectAds. Fail closed: success=true only after the readback reached the requested state. While the target has a lifecycle block (recorded when SetSystemState / EnableConfig / SetPlcState sent a runtime-changing request and then failed: data.lifecycleBlock) this tool returns LIFECYCLE_BLOCKED and does nothing: stop, report data.lifecycleBlock to the user, do not switch to another control channel (raw ADS, COM, DTE, GUI, console), and call ClearLifecycleBlock only after the user agreed. Consent (MCP server): through the TcAuto MCP server that question is asked by the server itself: when the target AmsNetId is not local-umrt (targetKind; unknown included), the first such call of this server session to that target makes the server ask the user in a confirmation form (MCP elicitation) before anything runs; local-umrt never asks. The AI cannot answer the form and a chat answer does not replace it. Refused: CONSENT_DECLINED (the user did not approve) or CONSENT_REQUIRED (the client cannot show confirmation forms, the form failed or timed out); nothing ran: stop and report, do not retry or work around it. The PowerShell module itself does not ask.
