# recovery: Read when a tool failed: what to stop, what to report, LIFECYCLE_BLOCKED, SYSTEM_EXCEPTION, UmRT crash, reload and issue reports.

## Always
1. Stop runtime-changing calls. Report `error.code`, `error.message`, `data.steps` / `data.lifecycleBlock` to the user.
2. Read-only diagnosis is fine: `GetStatus`, `GetSystemState`, `GetPlcState`, `GetBuildErrors`, `GetIdeModalDialog`.
3. Never work around it: no raw ADS WriteControl, no COM / DTE / `ExecuteCommand`, no GUI clicks, no runtime console input, no reconnecting the IDE after Activate, no changing Platform / Target / Route / ShouldBuild / PLC Disabled, no hard-coded AmsNetId. Do not move, delete or edit the lifecycle block file.

## LIFECYCLE_BLOCKED
An earlier runtime-changing request (SetSystemState / EnableConfig / SetPlcState) was sent and then failed. While the block exists, runtime-changing tools do nothing. Report `data.lifecycleBlock`, wait for the user. Only after the user agreed: `ClearLifecycleBlock` with Reason / FallbackMethod / AllowedSideEffects / MaxVerifyLevel in the user's words, then run the lifecycle again from the start; do not claim more than MaxVerifyLevel. A bridge killed during a request (`IDE_MODAL_DIALOG` / `BRIDGE_TIMEOUT`) turns into an `INTERRUPTED` block on the next runtime-changing call: same handling.

## SYSTEM_EXCEPTION (TwinCAT in Exception)
Do not recover it yourself. With the user's consent: fix the PLC code that raised it (Error List row `Exception (Exception Code: ...)`), on a local UmRT restart the UmRT first (a UmRT process that had a PLC exception can crash again later), `GetSystemState` reads Config, then `EnableConfig Force=true`. In Exception again right after Activate (boot project autostart): stop and report, do not repeat.

## RUNTIME_CRASHED (local UmRT gone)
A lifecycle block is recorded. The user restarts the UmRT; do not restart the service or kill processes yourself. Then, after the user agreed, `ClearLifecycleBlock` and `EnableConfig Force=true`.

## LICENSE_MISSING
Never press the license dialog. Report; the user renews the trial license or activates the license in XAE, then `ClearLifecycleBlock` after the user agreed.

## Other frequent codes
- `RUNTIME_STATE_MISMATCH`: read `data.finalCheck` / `data.diagnostics`; `BOOT_PACKAGE_MISMATCH`: `EnableConfig Force=true` rewrites the Boot folder (after the user agreed).
- `IDE_MODAL_DIALOG`: `GetIdeModalDialog`; report dialogs with a choice.
- `BUILD_REQUIRED`: `BuildProject` until `completeBuild=true`.
- Details per error code: docs/troubleshooting.md of the TcAuto installation.

## Reload and issue reports
- `ReloadRuntime` switches to the installed runtime version; `ReloadModule` reloads only the PowerShell module. Both are refused while a lifecycle block exists. Afterwards `ConnectIde` again.
- `ReportIssue`: builds a de-identified issue text; only the user opens and submits it.

## Tool reference
Full behaviour of the tools of this topic (their descriptions keep the short form).

### ClearLifecycleBlock
Remove the LIFECYCLE_BLOCKED record of one target. Call it ONLY after the user has seen the block (data.lifecycleBlock of the refused tool: command, errorCode, requestedState, reachedState, message, time) and agreed; never call it on your own to get past LIFECYCLE_BLOCKED. A block is recorded when SetSystemState (any failure after its state request was sent, RUNTIME_CRASHED included), EnableConfig (any failure after set-config / Activate was sent, ACTIVATE_FAILED and NOT_CONNECTED / BUILD_REQUIRED of the nested login included; failures before that, such as BUILD_REQUIRED, PLATFORM_* or PLC_PROJECT_NOT_FOUND of PlcProjectPath, record nothing) or SetPlcState (Run / Stop not reached) sent a runtime-changing request and then failed; while it exists SetSystemState, EnableConfig, PlcLogin, SendPlcProgram, SetPlcState, WriteVariable, RunTest, RunTestCycle, RunLifecycle (at its EnableConfig step) and SetTcComParameter Online=true DryRun=false return LIFECYCLE_BLOCKED and do nothing. Read-only tools are not blocked. Structured receipt, all four required and filled in with the user's words, never invented: Reason = why the user approved lifting the block; FallbackMethod = how the work continues afterwards; AllowedSideEffects = array of the side effects the user allowed (e.g. ["TwinCAT restart","PLC download"]; exactly ["none"] when none, never "none" together with another entry); MaxVerifyLevel = the highest layer the verification after this clear will reach, results must not claim more than it (None, SystemState, PlcState, VariableRead, TestObserved). An empty or invalid field returns LIFECYCLE_RECEIPT_INCOMPLETE (data.missing / data.invalid) and nothing is removed. AmsNetId defaults to the IDE target, then the ADS session; '<unknown>' (records of an unknown or loopback 127.x.x.x.y.z NetId, which block every target) and '<corrupt>' (an unreadable state file) are cleared by name; data.stillBlocking / data.next name what still blocks every target. data: cleared (the removed record, null when none), remaining (array of {key, record} still recorded: [] when nothing is left, null only when the state could not be read), remainingKeys (array of keys), stillBlocking, receipt (reason, fallbackMethod, allowedSideEffects, maxVerifyLevel, clearedAt, clearedAtUtc, ...; appended to lifecycle-block-history.jsonl under the state lock), receiptWritten (false + historyWarning when the receipt could not be appended: other bridges will NOT sync). Cross-bridge: another MCP bridge / PowerShell process that still holds the block in memory drops it once the state file no longer has it and the history has the receipt of exactly that record (same key, createdAtUtc and command; clearedAtUtc not in the future); otherwise it keeps blocking and data.lifecycleBlock.syncNote says why: then clear it through that bridge. The sync is a convenience, not a security boundary (the history is not tamper-proof). After clearing, run the lifecycle again from the start with the approved FallbackMethod; nothing clears a block automatically.

### ReportIssue
Build a de-identified, pre-filled GitHub new-issue URL (and the same title / body as text) for a problem found while using this server; it creates NOTHING, calls no GitHub API and no network, needs no token and no IDE / ADS connection (works while the IDE is blocked by a modal dialog and is not refused by LIFECYCLE_BLOCKED). Title is the one-line summary; Tool, Parameters, Result (the failing {success,error,data} object, error.hint is dropped), Expected and Notes are optional. User names in paths, this machine's names, URLs and host names, AMS NetIds (loopback stays), IPv4 / IPv6 / MAC addresses, e-mail addresses, object keys, project paths (a project file keeps only its file name, other folders are masked, TIPC^ tree paths keep only TIPC) and secrets are masked; the name of the open solution is masked everywhere; ExtraMask lists literal strings (customer / site / person names) to hide as well. A token split across two lines is not recognised. data.masks / data.maskReport say what was masked. The encoded URL is capped at MaxUrlLength (default 7000): the largest of Result / Parameters / Notes / Expected is shortened and ends with [truncated] (data.truncated); data.body is always the complete de-identified text. The repository is PUBLIC: show data.maskReport and data.body to the user; ONLY THE USER opens data.url in a browser signed in to GitHub, reviews the text and submits it. Never open or submit it yourself. The environment section uses only what the server already holds in memory (module version / commit, PowerShell, OS, IDE ProgId, TwinCAT.Ads.dll version; the solution file name only with IncludeSolutionName=true); XAE / TwinCAT version is not read, put it in Notes. Inputs are masked first and the masked text is cut afterwards at a word boundary (10000 characters per text, 3000 per JSON string; never a prefix of a secret), so data.body is complete only with respect to that bounded input. Folder names of masked paths, dotless route names (CX-xxxxxx, name:48898) and non-ASCII e-mail addresses are masked as well.

### ReloadModule
Load the TwinCATAutomation PowerShell module again: the bridge process is retired and a new one imports the module from ModulePath (omit it to reload the module path loaded now). ModulePath must be src\TwinCATAutomation\TwinCATAutomation.psm1 of the main checkout the server was started from, or the same file in one of that repository's git worktrees (the entries of `git worktree list`); any other path is refused with RELOAD_PATH_NOT_ALLOWED (data.allowed lists the accepted paths). Fail closed: while the loaded module holds a lifecycle block in memory the reload is refused with RELOAD_LIFECYCLE_BLOCKED and nothing changes; report data.lifecycleBlocks to the user, ClearLifecycleBlock only after the user agreed. BUILD_REQUIRED entries the module holds in memory are written to build-required.json first (data.buildRequiredPersisted lists the ones that were missing there); when that file cannot be read or written the reload is refused with RELOAD_BUILD_REQUIRED and nothing changes. The IDE and ADS connections are released first (DisconnectIde without Quit: the IDE keeps running; DisconnectAds): run ConnectIde (and ConnectAds) again after the reload. Returns data.previous and data.current = {modulePath, moduleCommit, moduleDirty, moduleSource, loadedAt} (as GetStatus data.bridge: in a git checkout moduleCommit is the 40-character git sha HEAD pointed at, read from the .git files, and moduleDirty is null because uncommitted working-tree changes are not reflected). A new module that fails to import returns RELOAD_FAILED; the previous module path is then started again (data.restored). Only the PowerShell module is reloaded: the MCP server (index.js, bridge.ps1) and its tool list (tools.json) stay those of the running server; a cmdlet or parameter the new module adds is not offered until the server restarts. Installed runtime (GetStatus data.bridge.runtime.source "installed"): only the loaded module can be reloaded (omit ModulePath); to switch to another version run scripts/Install-TcAutoRuntime.ps1 in the checkout, then ReloadRuntime (a tool of the launcher): it replaces the whole runtime (index.js, bridge.ps1, tools.json and the module) and refreshes the tool list.
