# open-project: Read before opening a solution or choosing the target (IDE, ProgId, AmsNetId, platform).

## Steps
1. `GetProjectVersion SolutionPath=<.sln>` (offline): tell the user the TwinCAT version and which IDE will open it.
2. `ConnectIde SolutionPath=<.sln>` without ProgId. Several XAE installed and no match -> `PROGID_REQUIRED`: pass `ProgId`.
3. Take the AmsNetId from `ConnectIde data.amsNetId`; never hard-code one. Read `data.targetKind`: `local-umrt` = UmRT on this PC; anything else is a real machine (GetGuide('consent')).
4. Another target: `GetStatus AmsNetId=<id>` first (its `targetKind`), then `SetTarget AmsNetId=<id>`. Platform: UmRT / TwinCAT/BSD = `TwinCAT OS (x64)`, Windows RT = `TwinCAT RT (x64)`. `PLATFORM_UNKNOWN` -> pass `Platform`.
5. Read code: `GetProjectTree` -> `GetPouCode`.
6. Finish: `DisconnectIde` (`Quit=true` only for an IDE this session launched).

## When it fails
- `IDE_ATTACH_CONSENT_REQUIRED`: the IDE is not TcAuto's (the user opened it, or it already has the .sln open). Ask the user; yes -> `ConnectIde ProcessId=<pid>` (plus `SolutionPath`); no -> the user closes that solution, then `ConnectIde SolutionPath`. Never start a second IDE for the same solution.
- `IDE_MODAL_DIALOG` / `MODAL_SCAN_INCOMPLETE` / `IDE_BUSY`: `GetIdeModalDialog`; a dialog with one OK button you may close, anything with a choice: report it.
- `BRIDGE_TIMEOUT` of `ConnectIde` (slow cold start): call `ConnectIde` again with the same parameters.
- `IDE_LAUNCH_PENDING`, `ORPHAN_TAKEOVER_REFUSED`, `IDE_PID_*`, `REMOTE_MANAGER_MISMATCH`: follow `error.hint`. `TakeOverOrphan=true` only after asking the user.
- `PLATFORM_PROJECT_MISMATCH`, `BUILD_SELECTION_CHANGED`: nothing switched; report, the user fixes the Configuration Manager. Never change Platform / Target to get past a failure.

## Tool reference
Full behaviour of the tools of this topic (their descriptions keep the short form).

### ConnectIde
Connect to a running TwinCAT XAE / Visual Studio instance (found through the Running Object Table); only if none is found does it launch a new XAE. With a TwinCAT project loaded data.amsNetId is the target the IDE has; data.targetKind: local-umrt (the Usermode Runtime of this PC) | local-xar (the Windows XAR of this PC: a real machine) | remote | unknown (anything uncertain, never local-umrt), data.targetKindSource what decided it. SolutionPath is optional and opens that .sln after connecting. Attach rules: with ProgId only a running IDE with exactly that ProgID is an attach candidate (none = treated as no instance: that ProgId is launched, NoLaunch=true gives IDE_NOT_FOUND; never another ProgID). Without SolutionPath and without ProcessId the IDE selected as always (one with a TwinCAT project loaded first, else the first, busy ones last) is attached only when TcAuto itself launched it (ownedBySession) or it was bound with ProcessId in this module instance and not released by DisconnectIde since (consent kept in memory only, forgotten on DisconnectIde and on bridge / module reload); otherwise (e.g. the user opened it; also when an own IDE runs next to it - the selection does not switch to the own one) it is NOT attached, not modified (SilentMode untouched) and nothing is written: success=false, IDE_ATTACH_CONSENT_REQUIRED with data.candidates[] = every running IDE not launched by this TcAuto session and not consented (processId, 0 = pid unknown; progId, solutionPath when readable, startTime, mainWindowTitle), attached=false, launched=false, ownedBySession=false, requestedProgId. Ask the user whether TcAuto may work in that IDE (it turns on SilentMode; unsaved changes may be affected); yes: ConnectIde ProcessId=<pid>; no: ConnectIde SolutionPath=<sln> (plus ProgId if needed) to open another IDE. Never choose without asking; ProcessId is the only way to consent. No running IDE at all: unchanged (launch, or PROGID_REQUIRED). With SolutionPath the same rule applies to the IDE that already has that .sln open (an own one is preferred): not launched by TcAuto and not consented -> IDE_ATTACH_CONSENT_REQUIRED with data.reason solution-open-in-non-owned-ide, data.solution and data.candidates, nothing attached, changed or launched (both IDEs could save the same project files and overwrite each other's changes; inference, not measured); ask the user: yes -> ConnectIde ProcessId=<pid> SolutionPath=<sln>; no -> the user closes that solution there, then ConnectIde SolutionPath=<sln> again; never start a second IDE for it. Without SolutionPath data.reason is no-solution-path. Call this before any project, build or runtime tool. Returns ideProcessId, connectSec (total seconds), launchSec (only when a new IDE was launched: seconds until DTE was ready) and, when a solution is open, the detected target AmsNetId. When the IDE that has SolutionPath open is blocked by a modal dialog or busy (its DTE answers RPC_E_CALL_REJECTED or an empty Version), it is recognised without COM and IDE_MODAL_DIALOG (or IDE_BUSY without a dialog) is returned with data.ideProcessId, data.dialog, data.matchedBy and data.attached; no second IDE is launched. matchedBy module-state (the IDE this server was connected to), session-record (an earlier ConnectIde saw this process with this solution) or dialog-path (the dialog names a file in the solution folder) attach that IDE (attached=true) when TcAuto may work in it (else IDE_ATTACH_CONSENT_REQUIRED, attached=false, with the same diagnostics): GetIdeModalDialog / ResetSolution work on it right away. window-title (title = solution name only; may be a same-named copy elsewhere) does not attach (attached=false); when that IDE is not yours, LaunchIfBlocked=true ignores it and launches. After the dialog is closed the same ConnectIde call connects to it. Launching without ProgId: the IDE is chosen from the TcVersion of every .tsproj the .sln references and launched only when its TwinCAT XAE version equals that TcVersion, or for a project older than 4026 in the 32-bit TcXaeShell (TcXaeShell.DTE.15.0, XAE 4026) when the Remote Manager folder of exactly that TcVersion (Build_<build>.<revision> with a .dll) is installed; after opening, TcRemoteManager.Version of that IDE is read back: data.remoteManagerVerified true, or false + remoteManagerWarning when unreadable, or REMOTE_MANAGER_MISMATCH (data.expected / actual; nothing saved, COM released, the IDE stays owned: DisconnectIde Quit=true Kill=true) (data.progIdSelectedBy explicit / running-instance / tsproj-version / remote-manager-match / only-one-registered, evidence data.solutionVersion, the folder in data.solutionVersion.remoteManager); otherwise nothing is launched: PROGID_REQUIRED (pass ProgId) or IDE_VERSION_NOT_REGISTERED. With several IDEs installed pass ProgId or a SolutionPath with a readable .tsproj TcVersion. Never a second IDE for a solution this session already launched: that IDE is waited for (up to 60 s, also with NoLaunch) and attached (selectedBy session-launched), else IDE_LAUNCH_PENDING (data.probe; pid-unconfirmed = its pid could only be guessed, nothing attached: close it yourself, then DisconnectIde ForgetPendingLaunch=true; progid-mismatch = it was launched with another ProgId; other-session = launched by another TcAuto session, data.otherSession.hostState alive / gone). Exception: when that IDE has NO solution and no document open, its record is valid with a confirmed pid, host and owner are gone and ProgId (when given) equals the launch ProgId, it is reused without TakeOverOrphan (it was left by a cold start that failed, e.g. MODAL_SCAN_INCOMPLETE): attached, SolutionPath opened in it, owned by this session (selectedBy empty-orphan-reuse, data.reusedEmptyOrphan=true, data.previousOwner; DisconnectIde Quit=true closes it); a modal dialog or incomplete scan there returns IDE_MODAL_DIALOG / MODAL_SCAN_INCOMPLETE (nothing attached, no second IDE: close it, then the same ConnectIde again); an empty IDE without a launch record (opened by the user) is never reused. After a BRIDGE_TIMEOUT of ConnectIde (a slow cold start) call ConnectIde again with the same parameters, never launch an IDE yourself. An IDE whose launching session has ended (hostState gone) is taken over only with TakeOverOrphan=true (ask the user first whether anyone still works in it): solution, ended host, confirmed pid, the ROT DTE of that pid with the solution open and no modal dialog are all required, otherwise ORPHAN_TAKEOVER_REFUSED (data.reason) and nothing is attached; on success data.takenOver=true, data.previousOwner, ownedBySession=true. A reload prompt of that IDE is answered without reloading (solution Ignore, project No, file close) only when all of these hold: SolutionPath, a launch record of that .sln, its host and owner processes gone, confirmed pid, ProgId (when given) equal to the launch ProgId, the DTE of that pid in the ROT, and either that DTE has this .sln open or (DTE blocked) the prompt text names only files in the solution folder, or (no drive path in the text) the solution name in quotes. The first answer records reset-required for the .sln: BuildProject, EnableConfig, PlcLogin, SendPlcProgram, GenerateBootProject, SaveAsLibrary and every tool that saves a project file (AddPou, AddDut, AddGvl, AddInterface, AddLibrary, AddPlaceholder, FreezePlaceholder, RemoveReference, AddPlcTask, ImportPlcOpen, SetIndependentFile) return RESET_REQUIRED until ResetSolution (without SaveProjectChanges) reopened it from disk. On success data.reloadPromptAttempts, data.diskChangesNotLoaded=true, data.resetRequired (present = a prompt of this .sln was answered, now or earlier) and data.dirtyDocuments (unsaved editor documents only; ResetSolution also reads unsaved projects and the .sln, would drop them and refuses with UNSAVED_CHANGES unless Force=true). Any other dialog, a prompt without that evidence or one that stays up: IDE_MODAL_DIALOG with nothing attached (ResetSolution / DisconnectIde would answer NOT_CONNECTED): ask the user to close it in XAE, then call TakeOverOrphan again. ProcessId=<pid> binds ONLY that IDE process: never launches, never another instance; IDE_PID_NOT_FOUND (data.reason process-not-found / not-in-rot / invalid-pid) when the pid is not running or has no DTE in the ROT, IDE_PID_MISMATCH (data.reason progid / solution) when ProgId or SolutionPath does not match the IDE (an IDE with no solution open gets SolutionPath opened), IDE_MODAL_DIALOG / MODAL_SCAN_INCOMPLETE / IDE_BUSY with data.attached=false when its DTE is blocked. Ownership is unchanged: an IDE this session did not launch stays ownedBySession=false and DisconnectIde Quit=true refuses it (IDE_NOT_OWNED). Not together with TakeOverOrphan (INVALID_PARAMS).

### SetTarget
Set the target AmsNetId (ITcSysManager.SetTargetNetId, always done first: data.amsNetId, data.targetSet=true and data.targetKind even when the result is an error; targetKind: local-umrt (the Usermode Runtime of this PC) | local-xar (the Windows XAR of this PC: a real machine) | remote | unknown (anything uncertain, never local-umrt), data.targetKindSource what decided it.) and make the active solution platform follow the target. The target decides the platform: the active solution platform must match it (Usermode Runtime / UmRT and TwinCAT/BSD = 'TwinCAT OS (x64)', Windows RT target = 'TwinCAT RT (x64)'), otherwise EnableConfig fails with ACTIVATE_FAILED. Before switching, the project platform of the .tsproj under the chosen solution platform is checked: a solution platform that maps to another project platform (e.g. 'TwinCAT OS (x64)' -> 'TwinCAT OS (ARMT2)') returns PLATFORM_PROJECT_MISMATCH and nothing is switched (data.platformMap). Build selection: on 4026 a PLC's Disabled mirrors whether the ACTIVE configuration has a Build.0 for it (measured, 4026 VS2022 + TcXaeShell 64-bit), so a PLC disabled under one platform would be built, downloaded and started under another. Before switching, ShouldBuild of every PLC project under the target configuration is compared with the active one (data.buildSelection: plc, project, configuration, current shouldBuild/disabled, target shouldBuild, after): a difference (or a PLC disabled now that the target builds) returns BUILD_SELECTION_CHANGED (data.buildSelectionChanges) and nothing is switched; data that cannot be read returns BUILD_SELECTION_UNKNOWN (fail closed). A difference read back after the switch re-activates the previous configuration (data.restored) and returns BUILD_SELECTION_CHANGED; when that fails (restored=false) BuildProject and EnableConfig refuse with BUILD_SELECTION_CHANGED (data.buildSelectionGuard) until SetTarget switches back to the previous configuration (always allowed; clears it). With Platform that platform is activated for Configuration (default Release; data.platformCheck='parameter'). Without Platform the platform the target reports through TARGETINFO (ADS port 200, IG 0x700) is activated ('target'); not in the solution -> PLATFORM_NOT_FOUND. Target without TARGETINFO (ADS 0x702, data.adsError) and no Platform -> PLATFORM_UNKNOWN (NetId already set; nothing guessed). NoPlatformSwitch=true only sets the NetId ('disabled'). Returns data.platform (solution platform) / projectPlatform (active .tsproj) / requestedProjectPlatform / platformChanged / targetPlatform / targetPlatformSource and, when a platform was activated, configuration / previousPlatform / availablePlatforms / projectCheck / platformMap / platformMapReliable / platformMapReason / buildSelection / buildSelectionChanges. platformMapReliable=false: those entries are keyed <unknown #N> / <duplicate #N>; unknown entries are left out of availablePlatforms, a duplicate's name is listed once (platformMapReason gives the actual cause); the switch itself is still verified by readback. For the full map save the solution, then run SetTarget again: File > Save All in XAE, or BuildProject (measured, VS2022 VisualStudio.DTE.17.0 + TwinCAT 4026, registered tcauto: the build wrote the .sln back and the next SetTarget was reliable again; not tested on XAE Shell).
