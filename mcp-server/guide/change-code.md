# change-code: Read before writing or changing PLC code, creating POU / DUT / GVL / members, or editing project files on disk (includes the lint flow).

## Steps (through the IDE)
1. `LintCandidate ObjectKind=<kind> ObjectName=<name> Declaration=<text> Implementation=<ST> PlcProjectPath=<.plcproj>`: fix until it passes and `requiresDisposition` is false.
2. Write: existing object `WritePouCode`; new object `AddPou` / `AddDut` / `AddGvl` / `AddInterface` / `AddPouMember`, then `WritePouCode`.
3. `BuildProject`: must end with `data.completeBuild=true`; `BUILD_FAILED` -> fix from `data.codeErrors`.
4. `LintProject PlcProjectPath=<.plcproj>` (Scope All).
5. New PROGRAM: `AddPou` -> `AddPlcTask` -> `LinkProgramToTask` -> `BuildProject`.

## Steps (files edited on disk)
`LintProject` -> only when it passes `ResetSolution` -> `BuildProject` -> `LintProject`.

## Lint dispositions
- `requiresDisposition: true`: each `data.unresolved[]` entry is fixed in code or suppressed on the line above with `// tcauto-lint-disable-next-line <RULE-ID>: <reason>` (non-blocking rules only; blocking ones only through the user's `.tcauto\lint-profile.json`).
- List every `data.newSuppressions[]` and `data.newOverrides[]` to the user; do not commit them and do not `EnableConfig` / `RunLifecycle` before the user confirmed.
- `LINT_PARSE_FAILED`: `BuildProject` decides; a successful build = linter limitation, exclude the object in the profile with a reason.
- `LINT_CONTEXT_REQUIRED`: pass `PlcProjectPath`. `LINT_INCOMPLETE`: read `data.coverage.blockingRulesSkipped`.
- Never delete Compile items, reuse GUIDs or weaken the profile to get a pass.

## When it fails
- `BUILD_REQUIRED` from `EnableConfig` / `PlcLogin`: run `BuildProject` until `completeBuild=true`.
- `PLC_LOGGED_IN`: `PlcLogout`, then repeat the call.
- `UNSAVED_CHANGES` of `ResetSolution`: ask the user; `Force=true` only with their consent.
- `PROJECT_LOAD_ERRORS`: report `data.loadErrorFiles`, fix the XML (ask before restoring whole files), `ResetSolution`, build again.
- `LIBRARY_UNRESOLVED`: GetGuide('libraries').

## Tool reference
Full behaviour of the tools of this topic (their descriptions keep the short form).

### AddDut
Create a DUT (Struct / Enum / Union / Alias) in <Plc> Project^DUTs, write its declaration (TYPE ... END_TYPE from Fields / AliasType; an Enum without Fields gets enum_member := 0) and read it back. Fields is an ARRAY in declaration order: Struct / Union [{"name":"bStart","type":"BOOL"},{"name":"nCount","type":"INT","init":"0","comment":"..."}], Enum [{"name":"eIdle","value":0},{"name":"eRun","value":1}]; the old object form {"bStart":"BOOL"} is not accepted (INVALID_PARAMS: object key order is not kept). An invalid entry (name not an identifier, duplicate name, missing type, unknown key) -> INVALID_PARAMS, nothing created. After saving, the declaration read back is parsed and its member order compared with the input: a difference -> MEMBER_ORDER_MISMATCH (data.expectedOrder, data.actualOrder, data.declaration; the DUT exists, fix it with WritePouCode), never success; on success data.memberOrder is the order read back. data: path, objectKind (DUT), itemType (605 Enum / 606 Struct / 607 Union / 623 Alias), declaration, memberOrder. A name that already exists or a declaration that reads back different -> DUT_CREATE_FAILED. Change it later with WritePouCode Declaration only (a DUT has no implementation). BUILD_REQUIRED: a created DUT (also one whose readback failed) records kind code-changed for the open solution (data.buildRequired names the tool and the DUT; data.stateWarning when the state file could not be written): EnableConfig / PlcLogin / SendPlcProgram then refuse with BUILD_REQUIRED until BuildProject returns data.completeBuild=true. Project file: CreateChild changes the .plcproj only in XAE memory, so after the readback the project files are saved (DTE Project.Save of the .tsproj, with a deadline: PROJECT_SAVE_TIMEOUT + data.saveDiagnostics) and the .plcproj is read back from disk: success only when it has a <Compile Include> with the relative path of the object <folders>\<Name>.TcDUT (data.projectSaved: plc, plcproj, tsproj, savedFiles, verifiedFiles [file, preExisting], plcprojChanged, lastWriteBefore, lastWriteAfter, saveSec, warning); otherwise PROJECT_SAVE_FAILED (data.objectPath, createdInMemory=true, savedToDisk=false: the object exists only in XAE memory; error.hint gives the next step, also when the .plcproj cannot be located) or IDE_MODAL_DIALOG. What else Project.Save writes (measured, 4026 VS2022): a dirty plain text document is NOT saved; whether unsaved content of a PLC editor (a POU edited in the GUI) is written was NOT verified. PLC still logged in (XAE: Cannot add an object because it affects a device you are currently logged into, measured) -> PLC_LOGGED_IN, nothing created and no BUILD_REQUIRED recorded: PlcLogout first, then call it again.

### AddPouMember
Add a Method, Property, Action, or a property Get / Set accessor below a PROGRAM / FUNCTION_BLOCK / INTERFACE (Get / Set: below a property) and read it back (CreateChild, TE1000 v1.7.0 6.5.5). ParentPath: full tree path (TIPC^<Plc>^<Plc> Project^POUs^FB_Motor; for Get / Set ...^FB_Motor^P_Speed) or a name as for GetPouCode (FB_Motor, FB_Motor.P_Speed). Sub type / vInfo (measured, self-built client): FB / PROGRAM parent Method 609 {language, ReturnType, Access}, Property 611 {language, ReturnType, Access}, Action 608 {language}; INTERFACE parent Method 610 {ReturnType}, Property 612 {ReturnType}; property parent Get 613 / Set 614 {language, Access}. ReturnType is required for a Property, optional for a Method, not allowed for Action / Get / Set; Name is not needed for Get / Set. Access PUBLIC / PRIVATE / PROTECTED / INTERNAL is checked by the module (XAE makes any other value PUBLIC silently) -> POU_MEMBER_INVALID; wrong parent kind, Access / Language on an interface member -> POU_MEMBER_INVALID. Get / Set below an INTERFACE property (654 / 655) -> POU_MEMBER_UNSUPPORTED (reading such an accessor crashed VS2022); Get / Set with Access other than PUBLIC or Language other than ST -> POU_MEMBER_UNSUPPORTED (accessor-not-measured); a Method without ReturnType only with PUBLIC + ST (its language is reported, not checked). Same name below the parent (case-insensitive) -> POU_MEMBER_EXISTS (data.existingPath). Ambiguous parent name -> POU_AMBIGUOUS (data.candidates). Modal dialog -> IDE_MODAL_DIALOG, PLC logged in -> PLC_LOGGED_IN (PlcLogout first); nothing created in these cases. Success only after the new item is found with the expected ItemType and its declaration names the member, access and type (an action has none; method / action language checked). data.path = full tree path of the member: pass it as PouPath to GetPouCode / WritePouCode. A property gets no Get / Set by itself: add them with Kind Get / Set. Failure after CreateChild -> POU_MEMBER_CREATE_FAILED naming the step (the member stays in the tree). BUILD_REQUIRED: a created member records kind code-changed (data.buildRequired). No project file save is needed (the parent .TcPOU is written at once, the .plcproj does not change).

### BuildProject
Build the PLC project of the open solution and wait for the result. On BUILD_FAILED read data.codeErrors (description/file/line taken from the XAE Error List) instead of guessing. A build without compiler errors whose Error List still has rows XAE wrote while LOADING a project file returns PROJECT_LOAD_ERRORS (success=false, buildSucceeded=true, codeVerified=false, completeBuild=false, data.loadErrorItems / data.loadErrorFiles; BUILD_REQUIRED kept; rows of a disabled PLC only warn: data.disabledLoadErrorItems + warningCodes PROJECT_LOAD_ERRORS): report data.loadErrorFiles to the user, compare with version control and fix the XML (ask the user before restoring whole files), ResetSolution, build again. TE1200 Static Analysis rows (code SA<nnnn>, Error severity, the build still succeeds) are listed in data.staticAnalysisItems with data.warningCodes STATIC_ANALYSIS_ERRORS and do not change completeBuild. data.errors counts CODE errors only; missing / unresolved libraries (Library Manager rows such as "Could not open library") are counted separately in data.libraryErrors and listed in data.libraryErrorItems. With library errors the PLC code may not have been compiled at all (no code error is then reported), so a build that would otherwise succeed returns LIBRARY_UNRESOLVED (success=false, buildSucceeded=null, codeVerified=false): install the missing libraries in the XAE Library Manager first; AllowUnresolvedLibrary=true accepts it as success with data.warningCode=LIBRARY_UNRESOLVED, but such a build is never complete (data.completeBuild=false) and keeps BUILD_REQUIRED, so EnableConfig / PlcLogin still refuse. data.codeVerified=true means the Error List was read, lists no library error and no code row without a line, and every PLC project took part in the build: a PLC project skipped by the configuration (or none in the solution) gives codeVerified=false and data.warningCodes [PROJECT_SKIPPED_BY_CONFIGURATION, CODE_NOT_VERIFIED]; a success that is not verified that way (Error List unreadable, unlocated code rows) carries data.warningCode=CODE_NOT_VERIFIED. data.warningCodes lists every warning code (data.warningCode is the first). Breaking change: data.errors no longer includes Library Manager rows. data.errorItems keeps every Error List error except runtime / system log rows, each with category code | library | other (other = no file, e.g. a build-summary row). Runtime / system log rows ('<source>' (<number>): ..., optionally after a '<timestamp> | ' prefix as XAE shows them, e.g. TcUnit / ADSLOGSTR output 'PlcTask' (350): or 'TCOM Server' (10): / 'TwinCAT System' (10000):, with no file / line / compiler code / library message) are in data.runtimeMessages (category runtime) instead: never build errors, never in errorItems / warningItems / codeErrors; a row with that prefix that also has a file, line, code or library message stays in errorItems with a note (data.runtimeMessageNote). Such rows mean the PLC was online during the build (or are left from an earlier online session): when LastBuildInfo is not readable (decidedBy=ErrorList) and data.runtimeMessages is not empty, codeVerified=null and a success carries CODE_NOT_VERIFIED (not complete). With the PLC logged in XAE does not compile at all (measured): a BUILD_FAILED whose Error List lists no error row at all has codeVerified=null (never true) and reads the login state of each built PLC project into data.plcLoginState ([{plc, loggedIn true|false|null, source IsLoggedIn|ProduceXml|null, error}]; ITcPlcOnline.IsLoggedIn, else the ProduceXml OnlineSettings/LoggedIn of the PLC project - measured, ProduceXml decides; data.plcLoginState is null on every other result). A PLC read back as logged in sets data.plcOnlineSuspected=true with data.plcOnlineEvidence='login-state'; otherwise every built PLC project unknown plus runtime log rows sets it with 'runtime-log' (suspected only; a loggedIn=false read does not rule it out, it is only named in the message). plcOnlineSuspected / plcOnlineEvidence / plcLoginState are always present (false / null otherwise). With plcOnlineSuspected the hint (BUILD_FAILED_PLC_ONLINE) says: log out with PlcLogout, then BuildProject again; the usual summary stays in the message. data.failedProjects is SolutionBuild.LastBuildInfo: failed projects of the whole solution, the TwinCAT project included, not only PLC projects. data.decidedBy says what decided buildSucceeded (LastBuildInfo, else ErrorList). Warnings come with their contents: data.warningItems (same shape) and data.codeWarnings (without Library Manager items), unless data.errorListError is set. Build pane of the Output window: found by its GUID {1BD8A850-02D1-11D1-BEE7-00A0C913D1F8}, never by its localized name; data.buildPaneStatus read / not-found / unreadable, data.buildPaneName (as shown, e.g. Build or zh-TW 建置), data.buildPaneMessages (its non-empty lines, capped to the LAST 400 lines or 32000 characters; data.messages is the old field with the same capped list; when capped data.buildPaneTruncated = true and data.buildPaneLineCount = lines before the cap; both appear ONLY when capped), data.warningLines (the lines of the FULL pane with ': warning' after a file / location or at the line start (no compiler code needed: the 4024 XAE prints none), then capped to 200: data.warningLinesTruncated, data.warningLinesCount, only when capped; measured, other UI languages not verified); not-found / unreadable add data.buildPaneError and data.buildPanes and leave the lists empty. A full build can take several minutes: the build is started asynchronously and SolutionBuild.BuildState is polled (the synchronous VS2022 call never returns); TimeoutSec (default 600) bounds the wait, after which BUILD_TIMEOUT is returned; a modal dialog that appears during the build is returned as IDE_MODAL_DIALOG. Requires ConnectIde with an open solution. Coverage: data.projects lists every PLC project (.plcproj) with status built / skipped / failed / unknown / disabled (built / skipped from the active solution configuration, DTE SolutionContext.ShouldBuild) and a boolean disabled (from the TIPC tree, ITcSmTreeItem.Disabled of the PLC node, matched one to one by .plcproj path - the PLC node PlcProjectDef/ProjectPath - else by name; data.disabledMatchBy says path / name / null; an ambiguous match counts every project as enabled and sets data.disabledCheckError), data.skippedProjects, data.disabledProjects and data.coverageComplete. A PLC project that is disabled in the TwinCAT project (.tsproj Disabled="true", ITcSmTreeItem.Disabled) and not built has status disabled: it is listed in data.disabledProjects, not in data.skippedProjects, raises no PROJECT_SKIPPED_BY_CONFIGURATION and does not keep coverageComplete / codeVerified / completeBuild false; an ENABLED skipped project still does. When the PLC project list cannot be read every project counts as enabled and data.disabledCheckError is set. data.solutionConfiguration is '<configuration>|<solution platform>' read like GetIdeInfo (data.solutionPlatform equals GetIdeInfo solutionPlatform), data.projectPlatform the .tsproj project platform, data.platformSource how the solution platform was read (with 'context' solutionConfiguration is the configuration name only); each PLC project's own platform is data.projects[].platform. BUILD_REQUIRED (after a platform switch, or after a build that was not a complete success) is cleared only by a build with coverageComplete=true and codeVerified=true (data.completeBuild=true; never an AllowUnresolvedLibrary build). A build that ends LIBRARY_UNRESOLVED, BUILD_FAILED, BUILD_STATUS_UNKNOWN, BUILD_TIMEOUT or IDE_MODAL_DIALOG after it started, or succeeds with completeBuild=false records BUILD_REQUIRED for the solution (data.buildRequired; data.stateWarning when the state file could not be written), so EnableConfig and PlcLogin refuse until a complete build (not for a solution without PLC project). With accepted library rows and a code row without a line number data.warningCodes has LIBRARY_UNRESOLVED and CODE_NOT_VERIFIED. A PLC project that the active solution configuration does not build (no Build.0 in the .sln) is skipped silently by XAE while it still says Build succeeded: the result keeps success but sets data.warningCode=PROJECT_SKIPPED_BY_CONFIGURATION and data.warning. ExpectedProject=[names] makes a skipped project a failure (PROJECT_SKIPPED_BY_CONFIGURATION, build not started), an unknown name EXPECTED_PROJECT_NOT_FOUND, a disabled PLC project EXPECTED_PROJECT_DISABLED (build not started); use it whenever a specific PLC (e.g. a unit-test PLC) must be compiled.

### LintCandidate
Read-only and offline semantic lint of ONE PLC object BEFORE it is written: the candidate Declaration / Implementation is laid over the .plcproj on disk in memory (same name replaced, new object added) and checked with the LintProject rules, scoped to that object; nothing is written, no IDE, no ADS, no lifecycle block. Workflow: LintCandidate -> fix until it passes and requiresDisposition is false -> WritePouCode (or AddPou + WritePouCode) -> BuildProject -> LintProject. diagnostics list the candidate object; findings that appear in OTHER objects only with the candidate (e.g. a GVL constant set to 0 used as a divisor elsewhere) are in data.crossObject.newFindings (a blocking one -> LINT_FAILED, any -> requiresDisposition). Findings of OTHER objects that the disk project already has (e.g. TASK-001 of an uncalled PROGRAM) are in data.preExisting, outside verdict / unresolved / requiresDisposition (data.projectVerdict = the disk project without the candidate, its blocking findings in data.projectBlocking); findings of the candidate object itself stay in diagnostics. A pass is NOT a pass of the project: run LintProject after writing. A name a rule needs (FOR bound, array, divisor, loop condition) that the project cannot resolve, or that sits in an object whose file cannot be read -> LINT_CONTEXT_REQUIRED (data.candidate.contextRequired unresolved-identifier / context-object-broken), never a pass; in a project with library references an unqualified unknown name may be a library constant: coverage.rulesSkipped library-symbol-unresolved:<name> instead (only the rule that needs the value skips; do not declare it, that would shadow the library value). dispositionReasons candidate-not-analyzed: a section of the candidate was not analysed (conditional pragma ...), tell the user. ObjectKind: Program, FunctionBlock, Function, DUT, GVL, Interface, Method, Property, Action (Transition: LINT_INPUT_INVALID). ObjectName as WritePouCode PouName: FB_X, FB_X.M_Run, FB_X.P (property declaration), FB_X.P.Get (accessor). Implementation only ST. PlcProjectPath = path of the .plcproj (a PLC name needs the IDE: not supported, LINT_INPUT_INVALID); omitted = text-only (default profile): a candidate that needs the project (EXTENDS / IMPLEMENTS, Method / Property / Action, a type or identifier not declared in it and not elementary / standard / in the type catalog) gives LINT_CONTEXT_REQUIRED (data.candidate.contextRequired), never a silent pass. Overlay boundary errors (declaration keyword / name differs from ObjectKind / ObjectName, same name is another kind on disk, Parent missing) -> LINT_INPUT_INVALID. requiresDisposition=true -> fix each data.unresolved[] or suppress it inline with a reason (non-blocking rules only) and list every data.newSuppressions[] (new against the disk version of the object) and data.newOverrides[] to the user; no EnableConfig before that. data: as LintProject plus contextLevel (project / text-only), candidate {objectKind, objectPath, file, overlay replaced / added / text-only, contextRequired[]}, crossObject {checked, newFindings[], blocking}, preExisting[], projectVerdict, newSuppressionsBasis (candidate-vs-disk / candidate-text-only), newOverridesBasis. Errors: LINT_FAILED, LINT_PARSE_FAILED, LINT_CONTEXT_REQUIRED, LINT_INCOMPLETE, LINT_INPUT_INVALID, LINT_PROFILE_INVALID, LINT_BASELINE_INVALID, LINT_ENGINE_ERROR, LINT_ENGINE_UNAVAILABLE; each with error.hint.

### LintProject
Read-only and offline semantic lint of a TwinCAT PLC project ON DISK: reads the .plcproj, every file its <Compile> items list, the .tsproj that references it and the .sln; needs no IDE, no ADS, writes nothing, records no lifecycle block. Rules of this version: project integrity broken by editing files outside XAE (PROJECT-XML not well-formed / encoding / CDATA cut / required elements, PROJECT-KIND, PROJECT-NAME, PROJECT-GUID missing / malformed / duplicated / zero / hand-written, PROJECT-SUB, PROJECT-LINEIDS, PROJECT-COMPILE missing file / duplicate / file not compiled / SubType / Folder / case and escaping, PROJECT-LIB, PROJECT-TSPROJ .tsproj reference / GUID in .sln-.tsproj-.plcproj / tasks and PouCall, PROJECT-ENC) and ST parsing (LINT-PARSE-*); machine behaviour Build does not catch: SCAN-TEMPFB-001 (timer in METHOD / FUNCTION VAR), PROJECT-TASK-001 / 002 (PROGRAM never / twice per cycle), SCAN-LOOP-001 (busy-wait WHILE / REPEAT), SCAN-FOR-001 (FOR end value at the counter type limit), SCAN-ARR-001 (constant FOR range outside the array bounds), SAFETY-ARR-001 (constant index out of bounds), SAFETY-DIV-001 (division / MOD by constant zero). Use it after changing .TcPOU / .plcproj / .tsproj files directly: LintProject -> only when it passes ResetSolution -> BuildProject. Scope=Object checks only ObjectPaths (data.scope): a pass is NOT a pass of the whole project, run Scope=All before ResetSolution / BuildProject. Code the linter does not understand gives LINT_INCOMPLETE, never a pass. PlcProjectPath = path of the .plcproj file; or SolutionPath (.sln / .tsproj) with PlcProjectPath = the PLC name (several PLCs without a name: PLC_PROJECT_AMBIGUOUS, data.plcProjects). A PLC name without SolutionPath is not supported yet (LINT_INPUT_INVALID). passed=true does NOT mean the program is correct: only that the rules in data.rulesRun found no blocking finding in the analysed part; read data.coverage (notAnalyzed, blockingRulesSkipped, rulesNotRun) and data.unresolved with it. data: verdict (pass / fail / incomplete), passed (absent when nothing was analysed), diagnostics[] (ruleId, severity, blocking, machineImpact, blockableBasis = pending-measurement: XAE behaviour not measured yet but still blocking, file relative to the .plcproj directory, objectPath, section, line, column, message, evidence, fixHint), unresolved[] + requiresDisposition (machine-behaviour findings to fix), summary, coverage, profile {name, source, sha256, overrides[]: every setting weaker than the default}, baseline, source {plcProjectPath, solutionPath, tsprojPaths, ideChecked=false: XAE state is NOT compared with the disk in this version, save in XAE first}, engine {version, sourceHash}. Profile: .tcauto\lint-profile.json found from the .plcproj directory up to the solution directory (RuleProfile=default ignores it). Errors: LINT_FAILED (blocking finding; fix the files, never delete Compile items or reuse GUIDs to get a pass), LINT_PARSE_FAILED (run BuildProject: build succeeds -> linter limitation, exclude the object in the profile with a reason), LINT_INCOMPLETE, LINT_INPUT_INVALID, PLC_PROJECT_AMBIGUOUS, PLC_PROJECT_NOT_FOUND, LINT_PROFILE_INVALID, LINT_BASELINE_INVALID, LINT_ENGINE_ERROR, LINT_ENGINE_UNAVAILABLE (Constrained Language Mode / Add-Type blocked); each with error.hint.

### ResetSolution
Reload every project file from disk: dismisses the reload prompt if it is up (data.dismissedReloadPrompt). The XAE project prompt "The project file ... has been modified outside of TwinCAT XAE. Do you want to reload the project?" (a rewritten .plcproj; GetIdeModalDialog kind reload-prompt, reloadTarget project) is answered Yes by dialog control id (any UI language) and XAE reloads the project itself: then only ConnectIde runs again, no close / reopen (data.answeredYes=true, data.reopenedSolution=false, data.reloadTarget). A failed Yes is tried once more, then No (control id 7) with a full close / reopen; no WM_CLOSE (an MB_YESNO box ignores it, measured); every attempt is in data.reloadPromptAttempts, each waits at most what is left of TimeoutSec. The VS2022 solution prompt (a rewritten .sln; reloadTarget solution, recognised by button control ids 259 Reload + 1412 Ignore, measured VS2022 zh-TW) is answered Ignore (control id 1412), then the solution is closed and reopened from disk; not Reload: measured), Reload made VS ask at once to save the .tsproj left dirty by SetTarget. Before success the solution is read back until it is loaded again (data.loadCheck: FullName, IsOpen, SolutionBuild.ActiveConfiguration and, when the .sln references a .tsproj, TIPC with the PLC names the .tsproj lists; expectedFrom disk / memory / none); not loaded within TimeoutSec -> SOLUTION_RELOAD_INCOMPLETE, IDE crashed meanwhile -> IDE_CRASHED; a reload prompt that comes up during this readback is answered like the first one (at most 5 prompts per call, shared TimeoutSec), any other dialog -> IDE_MODAL_DIALOG. A reconnect answering MODAL_SCAN_INCOMPLETE is retried up to 3 times (data.reconnectAttempts). Otherwise it closes all documents without saving (data.closedDocuments), Solution.Close, Solution.Open of the same .sln on the same IDE, then ConnectIde again (20-25 s in total, data.totalSec). Use right after .TcPOU / .plcproj files were changed ON DISK by another tool while they are open in an XAE editor: otherwise XAE shows the modal "File has been changed outside the environment. Reload the new file?" (GetIdeModalDialog kind reload-prompt) and every call blocks. A file that is not open in an editor is picked up automatically within ~5 s and needs no call; WritePouCode / AddPou write through COM and never need it. Before closing, the PLC objects in XAE are compared with the .plcproj on disk (data.projectCheck, per PLC: checked, missingOnDisk [file, relativePath, fileExists], extraOnDisk, complete; a PLC whose .plcproj cannot be located, e.g. an independent .xti project file, gets checked=false + reason and is skipped). Nothing is saved by default: an object that XAE has and the .plcproj does not list cannot be told apart from one deleted on disk, so any missingOnDisk returns PROJECT_UNSAVED_CHANGES and nothing is saved or closed (extraOnDisk alone does not block: the reopen loads the disk version, XAE loses nothing). SaveProjectChanges=true keeps the XAE version: ONLY the project files are saved (.tsproj / .plcproj, DTE Project.Save with a deadline, PROJECT_SAVE_TIMEOUT) and read back (data.savedProjects); it is still refused (PROJECT_UNSAVED_CHANGES, data.saveRefused, plc '*' = not one PLC) when a reload prompt was handled first, the .TcPOU / .TcDUT / .TcGVL is missing at its relative path on disk, or any PLC of the same .tsproj (Project.Save writes every .plcproj below it) could not be compared, was compared incompletely or lists objects XAE does not have. DiscardProjectChanges=true keeps the disk version (closes anyway, XAE-only objects are dropped). The two exclude each other (INVALID_PARAMS). Unsaved changes of the IDE: before closing, every open document (Document.Saved), every project (Project.Saved, e.g. the .tsproj after SetTarget; BuildProject saves it again, measured) and the solution (Solution.Saved) are read; anything unsaved -> UNSAVED_CHANGES with data.unsavedCheck {documents, projects[{name, file}], solution, unchecked, error}, nothing saved or closed; unreadable (a Saved that reads null) -> UNSAVED_CHANGES too (fail closed, data.unsavedCheck.error); a busy / dead IDE, a dialog or a timeout during the read -> IDE_BUSY / IDE_CRASHED / IDE_MODAL_DIALOG / IDE_TIMEOUT, also with Force; a project that answers no DTE property at all (a TwinCAT Scope project, measured) is only listed in unchecked and named in data.stateWarning on success. Only top-level projects are read (not projects in solution folders, not the nested .plcproj). Ask the user whether to discard them; only with their consent call again with Force=true, which drops them and lists them in data.discardedChanges (unchecked projects as "may have been dropped"; unreadable state: discardedChanges null, discardedUnknown true). The Yes-only path reads nothing (unsavedCheck.checked false, forced false, forceRequested). DiscardProjectChanges=true is not that consent. WritePouCode writes the file on disk at once and leaves nothing unsaved (measured); a file changed on disk does not make the IDE copy unsaved, so the disk-edit flow is not refused unless the IDE itself holds unsaved changes. Do not use BuildProject to resolve PROJECT_UNSAVED_CHANGES (whether a build also saves PLC editor buffers is an inference, not measured). What else Project.Save writes (measured, 4026 VS2022): a dirty plain text document is NOT saved; whether unsaved content of a PLC editor (a POU edited in the GUI) is written was NOT verified. Unsaved library references / tasks / I/O are not detected. Any other modal dialog is reported as IDE_MODAL_DIALOG. Dialogs are checked before Solution.FullName is read and again after every poll of it that got no answer, so a reload prompt that XAE shows a few seconds after the disk change is handled in the poll and another dialog returns IDE_MODAL_DIALOG at once instead of RESET_SOLUTION_UNVERIFIED after TimeoutSec. A prompt that comes up later (during the project file check, before or during Documents.CloseAll / Solution.Close) is handled the same way: the reset starts over from the dialog step (nothing is closed before Solution.Close succeeds) and another dialog returns IDE_MODAL_DIALOG instead of PROJECT_SAVE_FAILED / SOLUTION_CLOSE_FAILED (real-machine check pending). The ADS connection is kept. BUILD_REQUIRED: a reload from disk (the files may have been changed outside the module) records kind code-changed for the open solution (data.buildRequired names the tool and the .sln; data.stateWarning when the state file could not be written): EnableConfig / PlcLogin / SendPlcProgram then refuse with BUILD_REQUIRED until BuildProject returns data.completeBuild=true.
