# deploy: Read before activating, downloading or starting a PLC (RunLifecycle, EnableConfig, PlcLogin, SetPlcState, SetSystemState).

## Steps
1. Check the target: `GetStatus` (or `GetStatus AmsNetId=<id>` for another target) -> `data.targetKind`. Not `local-umrt` = real machine: the tool asks the user in a confirmation form; tell the user what can happen (GetGuide('consent')).
2. One call: `RunLifecycle SolutionPath=<.sln>` (plus `TargetAmsNetId`, `Platform`, `PlcProjectPath` / `ExpectedProject` / `AdsPort` for multi-PLC solutions).
   Or step by step: `BuildProject` (completeBuild=true) -> `EnableConfig Force=true` -> `ConnectAds`.
3. Check: `GetPlcState` / `ReadVariable`.

`EnableConfig Force=true` already does Config, Activate, Run, Login, Download and PLC Run: `PlcLogin`, `SendPlcProgram`, `SetSystemState`, `SetPlcState` are rarely needed. Never add sleeps; the tools wait for the target state. After Activate do not reconnect the IDE; `ConnectAds` again (ReadVariable / WriteVariable reconnect by themselves).

## Platform
The target decides the platform: UmRT / TwinCAT/BSD = `TwinCAT OS (x64)`, Windows RT = `TwinCAT RT (x64)`. `EnableConfig` switches and rebuilds on a mismatch. `ACTIVATE_FAILED` = usually the wrong platform: pass `Platform`.

## When it fails
Stop runtime-changing calls and follow GetGuide('recovery'). Before anything ran (no block): `BUILD_REQUIRED` (build), `PLATFORM_*`, `BUILD_SELECTION_*` (report), `PLC_PROJECT_AMBIGUOUS` (pass `PlcProjectPath`), `PLC_PORT_MISMATCH` (`ConnectAds Port=<allowed port>`, then `GetPlcState`).

## Tool reference
Full behaviour of the tools of this topic (their descriptions keep the short form).

### EnableConfig
Activate the configuration on the target without any dialog. Restarts TwinCAT and downloads/starts the PLC program: the machine stops and restarts. With Force=true it runs the whole lifecycle: Config -> Activate -> wait for Run -> PLC Login+Download -> wait for port 851 -> PLC Run, and reports every step in data.steps. data.dialogsSeen lists the modal dialogs the watchdog saw while ActivateConfiguration ran, also on success (title, text, buttons, firstSeen, lastSeen, durationSec, scans; [] when none; durationSec is a lower bound, the dialog may have been up to about two scan intervals (~4 s) longer; at most 20 entries, data.dialogsDropped counts the ones not recorded, 0 when none); nothing is clicked. NoLogin=true stops after TwinCAT is in Run (no download, no PLC Run). TwinCAT restarts, so call ConnectAds again afterwards (ReadVariable/WriteVariable also auto-reconnect; data.reconnected tells you). Never add sleeps around this call; it polls until the target state is reached. Before Activate the active solution platform is compared with the platform the target reports through TARGETINFO (ADS port 200, IG 0x700; data.platformCheck='target'), else with Platform when given ('parameter'); the solution platform and the project platform of its .tsproj must both match; on a mismatch the solution platform is switched and the project rebuilt (steps platform-fix, platform-fix-build; data.platformFixed=true; not part of TimeoutSec). NoPlatformFix=true returns PLATFORM_MISMATCH instead, before anything is activated. A solution platform with the right name whose .tsproj is built for another project platform makes the switch return PLATFORM_PROJECT_MISMATCH (data.platformMap, data.requestedProjectPlatform; fix the Configuration Manager). A switch that would change which PLC projects are built returns BUILD_SELECTION_CHANGED (data.buildSelectionChanges: plc, configuration, current shouldBuild/disabled, target shouldBuild; on 4026 a PLC disabled under one platform is enabled under another, measured, 4026 VS2022 + TcXaeShell 64-bit), unreadable data BUILD_SELECTION_UNKNOWN; either stops before any build or activation (data.buildSelection / buildSelectionChanges / restored, see SetTarget). A target without TARGETINFO (ADS 0x702, e.g. the UmRT of TwinCAT 3.1.4026.21-22) and no Platform: platformCheck='skipped', data.warning set, Activate runs as before. data always has targetPlatform, targetPlatformSource (adsTargetInfo / unavailable), solutionPlatform, projectPlatform (.tsproj project platform), platformFixed, platformCheck. ACTIVATE_FAILED = ActivateConfiguration returned but XAE reported failed projects ('Check config failed!'; nothing written to the target), usually because the active solution platform (data.solutionPlatform) differs from the target platform: retry with Platform ('TwinCAT OS (x64)' for a Usermode Runtime / UmRT or TwinCAT/BSD, 'TwinCAT RT (x64)' for a Windows RT target). Multi-PLC: every PLC project (or PlcProjectPath) is logged in and started on its own ADS port (851, 852, ...; data.plcs). After Activate the project _Boot package is compared with the Boot folder of a target on this PC (data.bootPackage, BOOT_PACKAGE_MISMATCH). Step verify reads back port 10000 and every PLC port at the end and checks for a modal dialog: anything not Run is RUNTIME_STATE_MISMATCH (data.finalCheck), never success; failures after Activate carry data.diagnostics (dialog, Error List rows, bootPackage). LICENSE_MISSING: a dialog that is up or the step error with the runtime license failure ((10000) and a license word, e.g. license not found) replaces the code (error.message then starts with LICENSE_MISSING:, data.licenseMissing.evidence / originalCode); an Error List row alone may be stale and only adds data.licenseErrorListEvidence (code and hint kept); the lifecycle block is kept and the dialog is never pressed: stop and report to the user (renew the trial / activate the license in XAE, then ClearLifecycleBlock after the user agreed). BUILD_REQUIRED (nothing activated): after a solution platform switch or after a BuildProject that was not a complete success (LIBRARY_UNRESOLVED, BUILD_FAILED, completeBuild=false) there was no complete BuildProject; Activate would compile by itself without anybody checking the result. Also after WritePouCode / AddPou / AddDut / AddGvl / AddLibrary / ResetSolution (or the New-TcProject cmdlet) changed the PLC code or project (kind code-changed,; error.hint names the tool and object). After a BuildProject that did not prove the code compiled (codeVerified not true, e.g. unresolved libraries, also AllowUnresolvedLibrary=true) the module records BUILD_REQUIRED and EnableConfig does not activate, download or start until a complete build (EnableConfig has no AllowUnresolvedLibrary): when the build after an automatic platform switch succeeds with data.completeBuild not true, BUILD_REQUIRED is returned before set-config (message names codeVerified / warningCodes); install the missing libraries and run BuildProject until data.completeBuild=true. A solution never built or changed through these tools is not refused (known limit, see docs/troubleshooting.md BUILD_REQUIRED). RUNTIME_CRASHED of the set-config / set-run step (local UmRT process gone) is returned with its code and hint, crash data in data.runtimeCrash. Fail closed: success=true only after the readback reached the requested state. While the target has a lifecycle block (recorded when SetSystemState / EnableConfig / SetPlcState sent a runtime-changing request and then failed: data.lifecycleBlock) this tool returns LIFECYCLE_BLOCKED and does nothing: stop, report data.lifecycleBlock to the user, do not switch to another control channel (raw ADS, COM, DTE, GUI, console), and call ClearLifecycleBlock only after the user agreed. Consent (MCP server): through the TcAuto MCP server that question is asked by the server itself: when the target AmsNetId is not local-umrt (targetKind; unknown included), the first such call of this server session to that target makes the server ask the user in a confirmation form (MCP elicitation) before anything runs; local-umrt never asks. The AI cannot answer the form and a chat answer does not replace it. Refused: CONSENT_DECLINED (the user did not approve) or CONSENT_REQUIRED (the client cannot show confirmation forms, the form failed or timed out); nothing ran: stop and report, do not retry or work around it. The PowerShell module itself does not ask.

### PlcLogin
Login to the PLC project and download the program in one call (PLC_LOGIN_FLAGS Regular, prompts answered by SilentMode, no dialogs). Use after a successful BuildProject when TwinCAT is already in Run; EnableConfig Force=true already includes this step. With several PLC projects pass PlcProjectPath (PLC name such as FrameworkUnitTest or tree path); without it PLC_PROJECT_AMBIGUOUS is returned instead of logging into the first PLC. data.adsPort is the PLC's ADS port. Refused with BUILD_REQUIRED (every LoginMode, nothing sent to the IDE) while the solution needs a complete BuildProject (after a platform switch, a build that was not a complete success,, or a code / project change by WritePouCode, AddPou, AddDut, AddGvl, AddLibrary or ResetSolution (or the New-TcProject cmdlet),; error.hint names the tool and object): XAE compiles before a login by itself, but that compile is not checked. Fail closed: after Login the login state is read back (data.loggedIn, data.loginStateSource; ProduceXml OnlineSettings/LoggedIn of the PLC project); success only when it reads back true, false or unreadable -> LOGIN_FAILED (Login returning without an error is not proof: SilentFlag = Login(257) returns and stays logged out, measured). Fail closed: success=true only after the readback reached the requested state. While the target has a lifecycle block (recorded when SetSystemState / EnableConfig / SetPlcState sent a runtime-changing request and then failed: data.lifecycleBlock) this tool returns LIFECYCLE_BLOCKED and does nothing: stop, report data.lifecycleBlock to the user, do not switch to another control channel (raw ADS, COM, DTE, GUI, console), and call ClearLifecycleBlock only after the user agreed. The AI cannot answer the form and a chat answer does not replace it. ### SetPlcState
Switch the PLC runtime to Run, Stop or Reset and wait for the state. Reset leaves the PLC in Stop; call Run to recover. An older report that Reset kills TcSystemServiceUm on a UmRT target did not reproduce (measured, 4026 VS2022 + local UmRT). Run/Stop: when the last read of the PLC port failed (e.g. runtime crash) data.currentState / finalState is 'Unreachable', the last state read before is data.lastState and the error data.lastError; data.leftOriginal is true only when a read returned a state other than data.originalState, failed reads are data.unreachableSeen. TwinCAT system state: before anything is sent (Run, Stop and Reset) ADS port 10000 is read; Exception (adsState 19) returns SYSTEM_EXCEPTION and an unreadable port SYSTEM_STATE_FAILED, both with nothing sent and no lifecycle block (data.systemState, adsState, readAt / readError). A system in Exception was not recovered by a PLC Run or Reset (measured; Stop is refused conservatively). Without data.lifecycleBlock nothing was sent; with it (PLC Run step of EnableConfig) follow its stop instruction. Otherwise report it to the user, the recovery is EnableConfig Force=true after the user agreed: fix the PLC code that raised it (or confirm its trigger is gone), and on a local UmRT ask the user to restart the runtime first after any PLC exception (divide by zero 0xc0000094 or page fault 0xc0000005: the same UmRT process crashed seconds after a successful EnableConfig, measured, verified on local UmRT only). In Exception again right after that Activate (boot project autostart; user report, not measured): do not repeat it, stop and report. Run is success only when the PLC port AND port 10000 read Run in every round of a 1500 ms confirm window (at least 3 rounds; data.systemState, data.runConfirm; also when the PLC was already in Run); a port that leaves Run or cannot be read there returns RUNTIME_STATE_MISMATCH (data.reached=false) and records a lifecycle block when Run was sent (not when the PLC was already in Run). The window is not part of TimeoutSec. Fail closed: success=true only after the readback reached the requested state. While the target has a lifecycle block (recorded when SetSystemState / EnableConfig / SetPlcState sent a runtime-changing request and then failed: data.lifecycleBlock) this tool returns LIFECYCLE_BLOCKED and does nothing: stop, report data.lifecycleBlock to the user, do not switch to another control channel (raw ADS, COM, DTE, GUI, console), and call ClearLifecycleBlock only after the user agreed. Consent (MCP server): through the TcAuto MCP server that question is asked by the server itself: when the target AmsNetId is not local-umrt (targetKind; unknown included), the first such call of this server session to that target makes the server ask the user in a confirmation form (MCP elicitation) before anything runs; local-umrt never asks. The AI cannot answer the form and a chat answer does not replace it. Refused: CONSENT_DECLINED (the user did not approve) or CONSENT_REQUIRED (the client cannot show confirmation forms, the form failed or timed out); nothing ran: stop and report, do not retry or work around it. The PowerShell module itself does not ask.

### SetSystemState
Switch TwinCAT to Run or Config via ADS WriteControl (no StartRestartTwinCAT dialog) and poll until the state is reached. Switching to Config stops the runtime: all outputs go to zero. Does not download the PLC program; EnableConfig Force=true is the usual choice. Run sends AdsState Reset (2) and Config sends Reconfig (16) on port 10000 (data.sentAdsState; Run (5) is refused there with ADS 0x701). After the target state is seen it must hold for SettleSec (default 3 s) and is read back (data.readbackState, data.stateTrace): a runtime that falls back to Config (e.g. ADS 1809 symbol version invalid) returns SYSTEM_STATE_MISMATCH, never success. When the original state equals the target (Run -> Run restart) the system must first be seen leaving it. data: originalState, finalState, reached, held, leftOriginal, latencyMs; when it stays in / falls back to Config the license server (ADS port 30) is read (data.licenses) and data.diagnostics is added, the same shape as EnableConfig: dialog (XAE modal dialog title / text), dialogScanComplete, errorList (first XAE Error List errors), errorListError, bootPackage (Boot folder comparison of a target on this PC), modalScan; without an IDE connection dialog and Error List are not read (dialogScanComplete=false, modalScan.reason=no-ide, errorListError starts with unavailable), the error code never changes. error.hint follows the diagnostics: ADS 1809 / 0x711 / symbol version in the dialog or Error List -> the Boot package and the PLC .app differ (BuildProject, then EnableConfig Force=true); another dialog -> its text; a license is named only when the license server reported an expired / invalid one. A dialog with the runtime license failure ((10000) and a license word) returns LICENSE_MISSING (error.message starts with LICENSE_MISSING:, data.licenseMissing; the lifecycle block keeps the original code): stop and report to the user; an Error List row alone may be stale: only data.licenseErrorListEvidence, code kept. Local UmRT only: when its TcSystemServiceUm process (data.servicePidAtStart) disappears and port 10000 answers ADS 0x7 for 10 s, RUNTIME_CRASHED is returned at once (data.lastError, lastState, runtimeName, unreachableMs) instead of SYSTEM_STATE_TIMEOUT after TimeoutSec; when TimeoutSec ends while the last read fails and no TcSystemServiceUm of that runtime runs any more (process list readable) it is RUNTIME_CRASHED too (data.crashDetectedBy streak / deadline; a failure carries data.probeErrors and deadlineCheck for diagnosis); restart the UmRT, then EnableConfig Force=true. When the last read failed, finalState / currentState is Unreachable (data.lastState = last state read), never the old state; leftOriginal is true only when a read returned another state (unreachableSeen: any failed read after the request, also during the wait). Fail closed: success=true only after the readback reached the requested state. While the target has a lifecycle block (recorded when SetSystemState / EnableConfig / SetPlcState sent a runtime-changing request and then failed: data.lifecycleBlock) this tool returns LIFECYCLE_BLOCKED and does nothing: stop, report data.lifecycleBlock to the user, do not switch to another control channel (raw ADS, COM, DTE, GUI, console), and call ClearLifecycleBlock only after the user agreed. Consent (MCP server): through the TcAuto MCP server that question is asked by the server itself: when the target AmsNetId is not local-umrt (targetKind; unknown included), the first such call of this server session to that target makes the server ask the user in a confirmation form (MCP elicitation) before anything runs; local-umrt never asks. The AI cannot answer the form and a chat answer does not replace it. Refused: CONSENT_DECLINED (the user did not approve) or CONSENT_REQUIRED (the client cannot show confirmation forms, the form failed or timed out); nothing ran: stop and report, do not retry or work around it. The PowerShell module itself does not ask.

### RunLifecycle
Full PLC lifecycle in one call: ConnectIde -> SetTarget (only with TargetAmsNetId or Platform) -> BuildProject (unless SkipBuild) -> EnableConfig (Force, waits for Run, logs in and downloads unless NoLogin) -> ConnectAds -> GetPlcState (readback). PowerShell equivalent: Start-TcLifecycle (same parameters, steps and data fields). Pass TargetAmsNetId to select the UmRT/CX to activate on: a .tsproj without a saved target otherwise activates on the IDE default local runtime (ConnectIde data.amsNetId reports the target the IDE has). Platform is optional: EnableConfig compares the active solution platform with the platform the target reports through TARGETINFO (ADS port 200, IG 0x700) and switches + rebuilds on a mismatch. Runtimes that answer TARGETINFO with ADS 0x702 (e.g. the UmRT of TwinCAT 3.1.4026.21-22) report nothing: then pass Platform (e.g. "TwinCAT OS (x64)" for a Usermode Runtime / UmRT or TwinCAT/BSD, "TwinCAT RT (x64)" for a Windows RT target), which activates that solution platform in the SetTarget step before BuildProject (without TargetAmsNetId the AmsNetId reported by ConnectIde is used for it); without it a mismatch still ends in ACTIVATE_FAILED. Platform is also passed to EnableConfig (same value): it then finds the platforms equal and does not add the "-Platform was not given" warning (a platform the target reports through TARGETINFO still wins there); TargetAmsNetId without Platform calls SetTarget with NoPlatformSwitch=true (NetId only) and leaves the platform check to EnableConfig. Multi-PLC solutions: PlcProjectPath is passed to EnableConfig (only those PLCs are logged in and started), ExpectedProject to BuildProject (coverage check; not derived from PlcProjectPath), BuildTimeoutSec to BuildProject as TimeoutSec. ADS port of ConnectAds: AdsPort; without it the adsPort of EnableConfig data.plcs when they have exactly one distinct port (with or without PlcProjectPath); otherwise ConnectAds default 851. With PlcProjectPath and a non-empty data.plcs, an AdsPort that is not one of their adsPort values fails the ConnectAds step with PLC_PORT_MISMATCH (allowed ports in the message, nothing connected; EnableConfig already activated and, without NoLogin, logged in / Run). Example: PlcProjectPath ["FrameworkUnitTest"], ExpectedProject ["FrameworkUnitTest"], AdsPort 852. Readback: without NoLogin the GetPlcState state must be Run, otherwise RUNTIME_STATE_MISMATCH; with NoLogin it is only reported. Changes the running machine (TwinCAT restarts, PLC program is downloaded and started). Runtime-change consent: data.targetKind (ConnectIde / SetTarget / GetStatus) = local-umrt -> no confirmation. Anything else is a real machine (including a Windows XAR on this PC; unknown included): before the EnableConfig step the server asks the user in a confirmation form (MCP elicitation) the first time in this server session for that target; you cannot answer it and do not ask in chat instead. Refused -> the EnableConfig step fails with CONSENT_DECLINED (the user did not approve) or CONSENT_REQUIRED (the client cannot show confirmation forms, the form failed or timed out), nothing activated: stop and report, do not retry or work around it. Fail closed: while the target has a lifecycle block (an earlier SetSystemState / EnableConfig / SetPlcState sent a runtime-changing request and then failed) the EnableConfig step returns LIFECYCLE_BLOCKED (ConnectIde / SetTarget / BuildProject before it still run): stop, report the error and data.steps to the user, never retry through another control channel, and call ClearLifecycleBlock only after the user agreed. Stops at the first failing step; error is that step's error as it is. Error codes, data fields and the meaning of hints match Start-TcLifecycle; hint wording is not guaranteed to be identical (the LIBRARY_UNRESOLVED hint addition below is MCP only). data: steps[] ({name, success, code (error code of a failed step, else null), durationMs, result (raw step result)}), failedStep (null on success), plcProjects (EnableConfig data.plcs), adsPort (ConnectAds data.port), loggedIn (EnableConfig data.loggedIn), plcState (GetPlcState data.state), lifecycleBlock (the failed step's data.lifecycleBlock), targetKind / targetKindSource; fields of steps that did not run are null. A project with unresolved libraries stops at BuildProject with LIBRARY_UNRESOLVED (the PLC code may not have been compiled): install the libraries first. There is no AllowUnresolvedLibrary here: code whose build did not prove it compiled (codeVerified not true) is not activated, downloaded or started once the module recorded that build (known limits: BUILD_REQUIRED in docs/troubleshooting.md), so even after BuildProject AllowUnresolvedLibrary=true RunLifecycle SkipBuild=true stops at EnableConfig with BUILD_REQUIRED.
