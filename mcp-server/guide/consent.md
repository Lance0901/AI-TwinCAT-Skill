# consent: Read to know which calls the tool confirms with the user, which you ask yourself, and how to handle CONSENT_DECLINED / CONSENT_REQUIRED.

## The tool asks the user (confirmation form)
Only two cases, asked by the TcAuto MCP server itself (MCP elicitation). You cannot answer the form; a chat answer is not consent.
1. Runtime changes on a real machine: `RunLifecycle`, `EnableConfig`, `PlcLogin`, `SendPlcProgram`, `SetSystemState`, `SetPlcState`, `WriteVariable`, `RunTest`, `RunTestCycle`, `SetTcComParameter Online=true DryRun=false` when `targetKind` is not `local-umrt` (`local-xar`, `remote`, `unknown`; a Windows XAR on this PC is a real machine). Asked once per target per server session. Tell the user beforehand what can happen: TwinCAT restarts, the PLC stops and starts, outputs switch, axes can move.
2. `InstallPackage Approved=true`: every time. First call without `Approved` returns the plan; show `data.plan` to the user and ask; only after the user agreed call `Approved=true PlanToken=<data.planToken>`.

`local-umrt` (the UmRT on this PC): no confirmation; build, activate, run, write and test freely. The kind belongs to one AmsNetId: check another target with `GetStatus AmsNetId=<id>` first.

## Refused
`CONSENT_DECLINED` (the user did not approve) or `CONSENT_REQUIRED` (the client cannot show forms, the form failed or timed out, or a PlanToken this server did not issue) = nothing ran. Stop and report; do not retry, do not ask in chat instead, do not work around it. For `InstallPackage` the hint and `data.command` carry the tcpkg command the user can run in an elevated PowerShell.

## You ask the user yourself (no form)
- `AddAdsRoute`, `InstallLibrary` / `UninstallLibrary` (change this PC).
- `ConnectIde ProcessId=<pid>` after `IDE_ATTACH_CONSENT_REQUIRED`; `ResetSolution Force=true` (drops unsaved changes); `ConnectIde TakeOverOrphan=true`.
- Deleting: `DeleteChild`, `RemoveReference`, `UnlinkProgramFromTask`, `RemoveVariableLink`.
- `ClearLifecycleBlock`: only after the user saw `data.lifecycleBlock` and agreed.
- `requiresDisposition: true` lint results; any dialog with more than one button (report it, do not click).

## Tool reference
Full behaviour of the tools of this topic (their descriptions keep the short form).

### InstallPackage
Install a TwinCAT XAE or Remote Manager version with tcpkg. ASK THE USER FIRST: the user must see the plan and agree before any install. WITHOUT Approved=true NOTHING is installed: the result is a plan (success=true, data.executed = false) with data.plan (what to show the user), data.planToken (one use, about 10 minutes, valid only in this server process; a server / bridge restart drops it), data.command (the complete command, tcpkg install <PackageId>=<Version> -y), requiresAdministrator, isAdministrator, idesToClose, runningIdes[] {processId, name, path, title}, alreadyInstalled, versionInFeed, feedSources, availableVersions, buildFolder / buildFolderExists (Remote Manager), blockers[] (not-elevated, process-scan-failed, ide-running, tcpkg-running, version-not-in-feed) and data.hint. The plan lists the target package only: tcpkg resolves dependencies itself and -y confirms them too (data.dependencyNote). Show data.plan to the user and ask; call again with Approved=true AND PlanToken=<data.planToken> ONLY after the user agreed. Approved=true without a valid PlanToken (missing, unknown, used, expired, another command, or the state changed since the plan) -> TCPKG_PLAN_REQUIRED, nothing runs: make a new plan and ask again. Only %ProgramData%\Beckhoff\TcPkg\TcPkg.exe with a valid Beckhoff Automation GmbH & Co. KG Authenticode signature is run (TCPKG_NOT_FOUND / TCPKG_SIGNATURE_INVALID; a failed check fails closed). Never elevate, never close or kill IDEs yourself (an IDE this session opened only after the user agreed). With Approved=true and a valid PlanToken: already installed -> success, executed=false; not elevated -> TCPKG_ELEVATION_REQUIRED (no UAC prompt is opened); process list unreadable -> TCPKG_PRECHECK_FAILED; TcXaeShell / devenv running -> TCPKG_IDE_RUNNING (pids in data.runningIdes); tcpkg / Package Manager UI running -> TCPKG_RUNNING; version not on a configured feed -> TCPKG_VERSION_NOT_FOUND (data.availableVersions); then the install runs (TimeoutSec, default 1800) and tcpkg list -i is read back: success only when the version is listed (fail closed); TCPKG_INSTALL_FAILED (exit code not 0), TCPKG_TIMEOUT (tcpkg is NOT stopped and may still be installing: data.installProcessId; state unknown, nothing read back; wait for that pid to end, then GetPackageInfo; never rerun), TCPKG_INSTALL_UNVERIFIED (exit 0 but not listed). data.changedPackages = packages whose installed versions differ before / after; data.unexpectedChanges / data.warnings = changes other than PackageId (report them to the user), and a missing Build_ folder after a Remote Manager install. data.steps[] = query, install, readback. PackageId accepts only TwinCAT.Standard.XAE and TwinCAT.StandardRM.XAE (the runtime XAR is refused; dependencies are tcpkg's decision); feeds and the myBeckhoff account are the user's business. Version = an exact version from GetPackageInfo data.available[].version (e.g. 4024.71.5; the feed may not have the version that was installed before). Consent (MCP): Approved=true makes the server ask the user in a confirmation form (MCP elicitation) every time, showing the plan this server process returned for that PlanToken (a PlanToken this server process did not issue, or another PackageId / Version: CONSENT_REQUIRED without a form; make a new plan). The refusal hint and data.command carry the tcpkg command the user can run in an elevated PowerShell. Refused: CONSENT_DECLINED (the user did not approve) or CONSENT_REQUIRED (the client cannot show confirmation forms, the form failed or timed out); nothing ran: stop and report, do not retry or work around it. The PowerShell module itself does not ask.
