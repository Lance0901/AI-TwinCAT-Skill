# TwinCAT Automation Skill

用 TwinCATAutomation PowerShell 模組控制 TwinCAT 3 IDE(XAE)與 PLC runtime。全程無 dialog。

已知限制(beta)與真機驗證範圍:`docs/known-limitations.md`。遇到問題請開 GitHub issue(https://github.com/Lance0901/AI-TwinCAT-Skill/issues),附 tool 名稱、參數、回傳 JSON,以及 `Get-TcAutomationVersion`(MCP `GetAutomationVersion`)回的 version / commit。Canonical repository:https://github.com/Lance0901/AI-TwinCAT-Skill;安裝來源與 commit 記在 skill 目錄的 `tcauto-install-manifest.json`(#30)。

## Setup

任何操作前先匯入模組:
```powershell
Import-Module "<module-path>" -Force
```

## MCP server (alternative to Import-Module)

同一個模組也可以當 TcAuto MCP server 用(`mcp-server/`,stdio),不必在 shell 裡 `Import-Module`:每個 cmdlet 都是一個 MCP tool,tool 名 = CLI action 名(`ConnectIde`、`BuildProject`、`EnableConfig`、`ReadVariable`…,參數與 cmdlet 相同、以 JSON 傳),另加 5 個複合 tool:`RunLifecycle`(Connect→[SetTarget]→Build→Enable→ConnectAds→GetPlcState 讀回 一鍵,PowerShell 對等 cmdlet 是 `Start-TcLifecycle`,多 PLC 用 `PlcProjectPath` / `ExpectedProject` / `AdsPort`;`Platform` 選填:EnableConfig 會依 target 的 TARGETINFO 自動對齊 solution platform,target 不支援 TARGETINFO(ADS 0x702,例如這台的 UmRT)時要帶 `Platform="TwinCAT OS (x64)"`;`SetTarget` 有 `Platform` / `Configuration` / `NoPlatformSwitch`,`EnableConfig` 有 `Platform` / `NoPlatformFix`)、`QuickRead`(未連 ADS 時自動連再讀)、`GetStatus`(IDE/系統/PLC 狀態快照)、`GetIdeModalDialog`(偵測卡住 XAE 的 modal)、`ReloadModule`(#41,只在 MCP:bridge 重新 Import-Module,`ModulePath` 選填,只接受主 checkout 或其 git worktree 的 `src\TwinCATAutomation\TwinCATAutomation.psm1`,其他回 `RELOAD_PATH_NOT_ALLOWED`;記憶體裡有 lifecycle block 一律回 `RELOAD_LIFECYCLE_BLOCKED` 不 reload;記憶體裡的 BUILD_REQUIRED 先寫回 `build-required.json`,寫不了回 `RELOAD_BUILD_REQUIRED` 不 reload;reload 前先斷開 IDE/ADS,之後要重新 `ConnectIde`;回 `data.previous` / `data.current` 的 modulePath 與 git commit;`GetStatus` 的 `data.bridge.modulePath` / `moduleCommit` / `loadedAt` 顯示目前載入的模組)。When the `tcauto` MCP tools are available in the session, prefer them over Import-Module; they keep the IDE/ADS connection across calls. IDE COM 參考與 ADS 連線在呼叫之間保留,錯誤碼與 `error.hint` 和本頁相同;server 另加的 `BRIDGE_TIMEOUT` 代表 PowerShell 子程序被重啟、狀態全失,要重新 `ConnectIde`;`BRIDGE_DIED` 是 PowerShell 子程序自己結束(下一次呼叫會自動重啟,同樣要重新 `ConnectIde`;訊息含 "not executed; safe to retry" 的表示該呼叫根本沒送進 PowerShell,可直接重試);`MODULE_IMPORT_FAILED` 是 `powershell.exe` 起不來或 `Import-Module` 失敗(檢查 `TWINCAT_MODULE_PATH` / `TWINCAT_MCP_POWERSHELL`,每次呼叫都會回這個碼直到修好)。安裝:客戶機器用 release zip 的 `Install-TcAuto.ps1`(自帶 `node.exe`,註冊 Claude Code / Claude Desktop / Codex),開發者在 checkout 跑 `scripts\Install-TcAutoRuntime.ps1` 再註冊 launcher 一次;client 只註冊 launcher(`%LOCALAPPDATA%\TwinCATAutomation\launcher\tcauto-launcher.mjs`),不直接註冊 `mcp-server\index.js` 或專案 `.mcp.json`;換版後呼叫 launcher 的 `ReloadRuntime`(不在 tools.json,不用重開 client)。設定與完整 tool 表見 `docs/setup-mcp.md` 與 `mcp-server/README.md`;手動端到端腳本 `mcp-server/scripts/lifecycle-client.mjs`(用法見檔頭)。

## Full Lifecycle(零 dialog、零 Start-Sleep)

**整個 lifecycle 必須在同一個常駐的 PowerShell session 裡跑**(互動視窗、MCP server 或同一支腳本)。每一步開一個新的 `powershell.exe` 是錯的:行程結束時 COM 參考被釋放,`Connect-TcIde` 自己啟動的 XAE 會跟著關掉,後面的 Activate / Login 就失去同一個 IDE session(#32)。AI 工具沒有常駐 shell 時用 MCP server(`mcp-server/`),它就是常駐 host。

### Quick Start:一鍵 lifecycle(`Start-TcLifecycle`,MCP `RunLifecycle`,#27)

會重啟 TwinCAT、下載並啟動 PLC 程式:先問使用者。

```powershell
# Connect-TcIde -> [Set-TcTarget] -> Build-TcProject -> Enable-TcConfig -Force -> Connect-TcAds -> Get-TcPlcState 讀回(必須 Run)
$r = Start-TcLifecycle -SolutionPath "C:\Projects\MyProject.sln" -TargetAmsNetId <data.amsNetId> -Platform 'TwinCAT OS (x64)'

# 多 PLC:只 activate / login 指定的 PLC,Build 必須編到它,ADS 連它的 port
$r = Start-TcLifecycle -PlcProjectPath FrameworkUnitTest -ExpectedProject FrameworkUnitTest -AdsPort 852

Read-TcVariable -Path "MAIN.nCounter"   # ADS 已連好
```

- 參數 = `RunLifecycle` 的參數:`SolutionPath`、`ProgId`、`NoLaunch`、`TargetAmsNetId`、`Platform`、`SkipBuild`、`TimeoutSec`(Enable-TcConfig,預設 120)、`NoLogin`、`PlcProjectPath`、`ExpectedProject`(不會從 `PlcProjectPath` 推導)、`AdsPort`、`BuildTimeoutSec`。
- ADS port:`-AdsPort`;沒給時 `Enable-TcConfig` 的 `data.plcs` 去重後只有一個 port 就用它(不論有沒有 `-PlcProjectPath`),否則 851。有 `-PlcProjectPath` 時 `-AdsPort` 必須是選中 PLC 的 port 之一，否則 `PLC_PORT_MISMATCH`(不連線,message 列出允許的 port;已 activate,沒有 `-NoLogin` 時也已 login / Run)。
- 讀回:`-NoLogin` 以外 PLC 狀態必須是 Run,否則 `RUNTIME_STATE_MISMATCH`。
- Fail closed:第一個失敗的步驟就停,error 是該步的 error 原樣(`LIFECYCLE_BLOCKED` 照「Failure contract」停下回報),不重試、不換通道。
- `data`:`steps[]`(`name` / `success` / `code` / `durationMs` / `result`)、`failedStep`、`plcProjects`、`adsPort`、`loggedIn`、`plcState`、`lifecycleBlock`。

### 進階:分步執行

```powershell
# 1. 連 IDE + 開 solution(多實例時依 -SolutionPath 挑;data.candidates[] 列出全部)
$r = Connect-TcIde -SolutionPath "C:\Projects\MyProject.sln"

# 1b. 平台由 target 決定:UmRT(Usermode Runtime)/ BSD 是 'TwinCAT OS (x64)',Windows RT 是 'TwinCAT RT (x64)'
#     (Connect-TcIde 的 data.solutionPlatform / projectPlatform 看現在是哪個)。Set-TcTarget 不帶 -Platform 時讀 target 的
#     TARGETINFO 自動切;這台的 UmRT / XAR 回 ADS 0x702(不支援)→ PLATFORM_UNKNOWN,所以帶 -Platform:
Set-TcTarget -AmsNetId <Connect-TcIde 回的 data.amsNetId> -Platform 'TwinCAT OS (x64)'
#     (或 Enable-TcConfig -Force -Platform 'TwinCAT OS (x64)':Activate 前比對,不一致就切換 + 重新 Build)

# 2. Build(失敗回 BUILD_FAILED,逾時回 BUILD_TIMEOUT;data.errorItems[] 是 Error List 的錯誤明細:code/description/file/line)
#    data.projects[] = 每個 PLC project 的 built|skipped|failed|unknown|disabled,data.coverageComplete;
#    有 PLC project 沒在 active solution configuration 的 Build 清單 → data.warningCode = PROJECT_SKIPPED_BY_CONFIGURATION
#    (.tsproj Disabled="true" 的 PLC 沒 build 時是 disabled,列在 data.disabledProjects,不算缺口,#104)
#    指定一定要編到的 PLC(例如 unit-test PLC)就帶 -ExpectedProject,被跳過直接回失敗:
Build-TcProject -ExpectedProject FrameworkUnitTest

# 3. Activate 一步到位:Config -> Activate -> Boot package 比對 -> 等系統 Run(並確認停得住)
#    -> 每個 PLC Login+Download -> 等各 PLC port(851、852…)-> PLC Run -> 最後讀回 system + 每個 PLC port
#    已包含 Enter-TcPlcOnline 與 Set-TcPlcState Run,不要再加 Start-Sleep
Enable-TcConfig -Force

# 4. 連 ADS(AmsNetId 從 IDE target 自動偵測)
Connect-TcAds

# 5. 讀寫
Read-TcVariable -Path "MAIN.nCounter"
Write-TcVariable -Path "MAIN.bEnable" -Value $true
```

`Enable-TcConfig -Force` 細節:

| 項目 | 說明 |
|---|---|
| 流程 | Config → ActivateConfiguration → `boot-package`(專案 `_Boot\<platform>` 與 target Boot 目錄比 SHA-256)→ 等 port 10000 = Run 且停留 3 s → 每個 PLC `Enter-TcPlcOnline`(download)→ 等各 PLC port 可達 → PLC Run → 等各 port = Run → `verify`(最後讀回 10000 與每個 PLC port、檢查 modal dialog) |
| 多 PLC | 預設 TIPC 下每個 PLC project 都 login + Run,port 取 PLC 節點 XML 的 `<AdsPort>`(851、852…);`-PlcProjectPath FrameworkUnitTest` 只處理指定的。`data.plcs[]` = name / projectPath / adsPort / loggedIn / state |
| 不會假成功 | `verify` 有任何一個不是 Run(或有 modal dialog)回 `RUNTIME_STATE_MISMATCH`(`data.finalCheck`);Activate 後的步驟失敗時 `data.diagnostics` 附 dialog、Error List 前 10 筆、Boot package 比對;Boot package 不一致時 code 改成 `BOOT_PACKAGE_MISMATCH` |
| PLC Run | 模組 ADS session 正好是 `<netId>:<該 PLC port>` 才用 `Set-TcPlcState Run`;否則(例如 `Connect-TcAds -Port 10000` 或別台 NetId)用暫時的 client 送 Run,不動原 session |
| `ACTIVATE_FAILED` | `ActivateConfiguration()` 返回後讀 `SolutionBuild.LastBuildInfo`,> 0 = XAE 的 Check config failed(target 上什麼都沒寫,多半 solution platform 與 target platform 不符),`-Force` 流程停在 activate 那一步;hint 給 `Set-TcTarget -Platform` 指令 |
| `-NoLogin` | 跳過 download / PLC Run;只等 851 最多 10 秒(有 boot project 才會出現),沒有也不算失敗(step detail `skipped (no PLC port, -NoLogin)`)。之後依下方手動順序 |
| `-TimeoutSec` | 整個流程的總上限(單一 deadline),預設 120;每步等待用剩餘時間,超過 deadline 還沒開始的步驟回 `CYCLE_TIMEOUT` |
| data | `steps[]`(每步結果)、`plcState`(第一個 PLC)、`plcs[]`、`bootPackage`(status match/mismatch/unavailable、files[] 各自的 size/lastWriteTime/sha256)、`finalCheck`、`diagnostics`(失敗時)、`dialogsSeen`(#231:Activate 期間 watchdog 看到的 modal dialog,成功時也有;每筆 `title` / `text` / `buttons` / `firstSeen` / `lastSeen`(ISO 8601)/ `durationSec` / `scans`,沒看到是 `[]`;activate 步驟的 detail 附摘要;模組不會按任何按鈕)、`loggedIn`、`solutionPlatform`、`reconnected`(之前有 ADS 連線時自動重連;PLC Run 時已自動重連則 reconnect 步驟記 `already reconnected in step 6`) |
| 之後 | 若 Activate 前已 `Connect-TcAds`,不用手動重連;`Read/Write/Watch-TcVariable`、`Get/Set-TcPlcState` 也會自動重連,data 有 `reconnected` |

不想一步到位時的手動順序(每步都有 gating,不需 sleep):
```powershell
Enable-TcConfig -Force -NoLogin     # 系統 Run 後才返回
Enter-TcPlcOnline                   # Login(REGULAR=1)+ 全域 SilentMode:空 runtime 會建 app 並下載,已有 app 就 attach;之後 port 851 才存在(不要加 SILENT 旗標 257,會跳過建 app)。多 PLC 要帶 -PlcProjectPath <PLC 名稱>
Connect-TcAds                       # 先連 ADS,Set-TcPlcState 沒連線會回 NOT_CONNECTED
Set-TcPlcState -State Run           # 等 851 = Run 才返回(逾時回 PLC_RUN_TIMEOUT);PLC 未下載回 PLC_NOT_LOADED
```

## Failure contract(fail closed,#68)

**`success: true` 才代表目標狀態已讀回到達**;`success: false` 時不要把 data 裡任何欄位當成「已完成」(`Enable-TcConfig` 失敗時 `activated` / `restarted` / `loggedIn` / `reconnected` / `platformFixed` 一律是 `false`,實際送了什麼看 `activateSent`、`activateReturned`、`runSent`、`runReached`、`loginCompleted`、`platformSwitched`、`requestedState`、`reachedState`)。

### Stop conditions

遇到下列任一情況:**立刻停止所有會改變 runtime 的步驟**,後續步驟一律標示 NOT RUN,把 result(含 `data.lifecycleBlock` / `data.steps` / `data.finalCheck`)原樣回報使用者,只做唯讀診斷。

1. 任何 lifecycle cmdlet 回 `success: false`(不論 code)。
2. `error.code = LIFECYCLE_BLOCKED`(這個 target 之前的 postcondition 失敗還沒處理)。
3. 回傳 `data.lifecycleBlock`(這次失敗已記成 block)。
4. 讀回的狀態和你預期的不同(例如 `Get-TcSystemState` 是 Config,但你以為已經 Run)。

### Postcondition table

| Cmdlet | `success: true` 代表(已讀回) | 失敗會記 lifecycle block 的 code |
|---|---|---|
| `Set-TcSystemState` | port 10000 讀回 = 要求的狀態,且停留 `-SettleSec`(原狀態 = 目標時有先看到離開) | WriteControl 送出後的任何失敗:`SYSTEM_STATE_TIMEOUT`、`SYSTEM_STATE_MISMATCH`、`RUNTIME_CRASHED`、送出後的 ADS 例外(診斷認出 license 時回 `LICENSE_MISSING`,block 的 errorCode 仍是原本的碼) |
| `Enable-TcConfig`(無 `-Force`) | `ActivateConfiguration()` 返回、`LastBuildInfo` = 0、本機 target 的 Boot package 一致 | 送出 Activate 後的任何失敗(`ACTIVATE_TIMEOUT`、`ACTIVATE_FAILED`、`IDE_CRASHED`、`BOOT_PACKAGE_MISMATCH`…) |
| `Enable-TcConfig -Force` | `verify`:port 10000 = Run、每個 PLC port = Run(`-NoLogin` 只看系統)、沒有 modal dialog | set-config(Set-TcSystemState 真的送出 WriteControl)或 Activate 送出後的**任何**失敗,只有巢狀命令回的 `LIFECYCLE_BLOCKED` 不再重記:`ACTIVATE_TIMEOUT`、`ACTIVATE_FAILED`、`IDE_CRASHED`、`IDE_MODAL_DIALOG`、`LICENSE_MISSING`、`CYCLE_TIMEOUT`、`LOGIN_FAILED`、`STATE_SET_FAILED`、`ADS_RECONNECT_FAILED`、`SYSTEM_STATE_*`、`RUNTIME_CRASHED`、`RUNTIME_STATE_MISMATCH`、`BOOT_PACKAGE_MISMATCH`、`PLC_*`,以及 login 步驟巢狀 `Enter-TcPlcOnline` 回的 `NOT_CONNECTED` / `BUILD_REQUIRED`… |
| `Set-TcPlcState` | Run / Stop:該 port 讀回 = 目標;Reset:200 ms 後讀一次 | `PLC_RUN_TIMEOUT`、Stop 未到達的 `STATE_SET_FAILED` |
| `Enter-TcPlcOnline` / `Send-TcPlcProgram` | `Login()` 返回(`data.plcStateBefore` / `plcStateAfter` 是讀回值),不代表 PLC Run | 不記(只被擋) |
| `Write-TcVariable` | `WriteAny` 返回;`data.written` 是轉型後寫入的值 | 不記(只被擋) |
| `Invoke-TcTestCycle` | 每個 test case 都 Pass,且(沒有 `-KeepRunning` 時)PLC Stop 讀回到達 | 由內部命令記;PLC Run 失敗立即回(其餘步驟 `status = NOT RUN`),Stop 失敗整個 cycle `success: false`,都帶該步的 code / hint / `data.lifecycleBlock` |
| `Start-TcLifecycle`(MCP `RunLifecycle`) | 每一步 success,最後 `Get-TcPlcState` 讀回 Run(`-NoLogin` 只回報狀態) | 由內部命令記(`Enable-TcConfig`);第一個失敗的步驟就停,error 原樣、`data.failedStep`、`data.lifecycleBlock`;讀回不是 Run → `RUNTIME_STATE_MISMATCH`,`-AdsPort` 與選中的 PLC 不符 → `PLC_PORT_MISMATCH`(不記 block) |

還沒送出任何請求前的失敗(`BUILD_REQUIRED`、`BUILD_SELECTION_*`、`PLATFORM_*`、`AMS_NETID_REQUIRED`、`VARIANT_*`、`-PlcProjectPath` 找不到的 `PLC_PROJECT_NOT_FOUND`(在 set-config 之前檢查)…)什麼都沒改,不記 block;一旦 set-config(`Set-TcSystemState` 的 `data.requestSent = true`)或 Activate 已送出，同樣的 code 也會記。`RUNTIME_CRASHED` 也記 block:由使用者決定是否重啟 `TcSystemServiceUm`,不要自行重啟 service 或操作 console。

**請求途中行程被殺(#236)**:`Set-TcSystemState`、`Enable-TcConfig`、`Set-TcPlcState` 送出請求前先寫 in-flight 標記(`lifecycle-inflight.<pid>.<guid>.json`),返回時刪掉。行程在請求還沒回來時就死掉(MCP modal probe 殺 bridge 回 `IDE_MODAL_DIALOG` / `BRIDGE_TIMEOUT`、crash),當下不會有 block;**下一次 lifecycle 檢查**(任何行程的被擋命令或 `ClearLifecycleBlock`)才把它轉成 `errorCode = INTERRUPTED` 的 block。所以 bridge 被殺後的第一個會改 runtime 的呼叫就會回 `LIFECYCLE_BLOCKED`:照本節停下回報，不要重跑。已確認擁有者不在、卻轉不成 block(鎖不到、寫不了)時，所有 target 都擋(`state-unreadable`)。`Enable-TcConfig` 送出後有例外丟出 → `UNHANDLED_EXCEPTION`;`Enable-TcConfig` / `Set-TcSystemState` 被 Ctrl+C 停掉 → `INTERRUPTED`。細節見 `docs/troubleshooting.md`「LIFECYCLE_BLOCKED」。

**License 不足(`LICENSE_MISSING`,#49)**:Activate / 切 Run 後 runtime 回報 license 不足(跳著的 dialog 或這次步驟的錯誤訊息同時有 `(10000)` 和 license 字樣)時回這個碼,以 `error.code` 為準(`error.message` 以 `LICENSE_MISSING: ` 開頭)。直接呼叫模組時只有 `Enable-TcConfig` / `Set-TcSystemState -State Run` 會回;透過 MCP 時另加 modal probe 涵蓋的工具。Build、Login 等其他 cmdlet 遇到同一個 dialog 仍回 `IDE_MODAL_DIALOG`(看 `data.dialogText`)。Error List 的 license 列可能是舊的,只當參考(`data.licenseErrorListEvidence`),不改碼,取代 `IDE_MODAL_DIALOG` / `SYSTEM_STATE_*` / `RUNTIME_STATE_MISMATCH`(原碼在 `data.licenseMissing.originalCode`);MCP modal probe 看到 license dialog 時也回它(bridge 照樣重啟,被殺的請求照 #236 轉成 `INTERRUPTED` block)。**一律停下**:不按 dialog、不續 trial、不改 license 檔、不重跑;請使用者在 XAE 續 trial / 啟用 license,讀回後經使用者同意才 `Clear-TcLifecycleBlock`。Activate 前無法預檢(InfoSys 沒有方法,#49)。

### LIFECYCLE_BLOCKED(機器強制)

block 以 target AmsNetId 為 key 存在 `%TEMP%\TwinCATAutomation\lifecycle-block.json`(跨 `Import-Module -Force`、MCP bridge 重啟仍有效;不同 target 互不影響;解析不了 target、或 target 是 loopback NetId(`127.x.x.x.y.z`,例如 `127.0.0.1.1.1`)的命令遇到任何 block 都擋,寫給它們的 block 存成 `<unknown>`、擋所有 target;state 檔損毀時換成 `<corrupt>`、擋所有 target)。有 block 時下列命令回 `LIFECYCLE_BLOCKED`、什麼都不送:`Set-TcSystemState`、`Enable-TcConfig`、`Enter-TcPlcOnline`、`Send-TcPlcProgram`、`Set-TcPlcState`(所有 State)、`Write-TcVariable`、`Invoke-TcTest`、`Invoke-TcTestCycle`、`Set-TcComModuleParameter -Online -DryRun $false`(MCP:`RunLifecycle` 在 EnableConfig 步驟被擋)。唯讀命令(`Get-TcSystemState`、`Get-TcPlcState`、`Read-TcVariable`、`Get-TcSymbols`、`Connect-TcAds`、`Build-TcProject`、`Get-TcIdeModalDialog`…)不擋。成功的命令**不會**自動清掉 block。

### 禁止的自動 fallback

沒有使用者對「這個方法、這個 target」的明確同意前,一律不做:

1. 直接建立 `TcAdsClient` 呼叫 `WriteControl`。
2. `ITcSysManager.StartRestartTwinCAT()`。
3. `DTE.ExecuteCommand("TwinCAT.*")`。
4. Activate 後重新 `Connect-TcIde`(見「重要注意」第 3 點;`Invoke-TcTestCycle` 也不再這樣做)。
5. 用 GUI 點 TwinCAT toolbar。
6. 對 `TcSystemServiceUm` console 輸入 `r` / `c`。
7. 寫死 AmsNetId 或沿用聊天內容裡的 AmsNetId(一律從 `Connect-TcIde` / IDE target / `Connect-TcAds` 取得)。
8. 自動修改 Platform、Target、Route、ShouldBuild 或 PLC Disabled 來「讓它過」。

`scripts/check.ps1` 的 `forbidden` 檢查會擋 repo 程式碼(含字串)裡任何 `WriteControl` / `WriteControlAsync`、`StartRestartTwinCAT`、任何 `ExecuteCommand` 與寫死的 AmsNetId;合法用途要在該行(或正上方只有註解的那行)以註解加 `# tcauto-allow(<rule>): <理由>`(字串裡的標記不算)。

### 人工核准流程

1. 停止,回報 `data.lifecycleBlock`(command、errorCode、requestedState、reachedState、message、time)與診斷結果。
2. 等使用者確認原因並同意繼續。

## 通用 tree tool:先 dry-run,優先使用專用 tool

`LookupTreeItem` / `ProduceXml` / `CreateChild` / `ConsumeXml` / `DeleteChild` / `ExportChild` / `ImportChild`(cmdlet 見下表)直接對應 Automation Interface 的 `ITcSmTreeItem`,能碰到大部分組態,也最容易改壞。**第 1 期新增,還沒有真機實測(等 task 2.8)。**

1. **有專用 tool 就用專用的**:POU / DUT / GVL → `Add-TcPou` / `Add-TcDut` / `Add-TcGvl`,程式碼 → `Write-TcPouCode`,library → `Add-TcLibrary`,I/O 掃描 → `Invoke-TcIoScan`,link → `Set-TcVariableLink`。通用 tool 只在沒有專用 tool 時用。
2. **先查**:`Get-TcTreeItem` 確認完整路徑(不接受 `*` `?`),`Get-TcTreeItemXml` 看實際 XML 結構。
3. **先 dry-run**:修改類預設 `DryRun=true`,不呼叫任何修改 API。看 `data.changes`(ConsumeXml 的 current / planned)、`data.plannedPath`(CreateChild)、`data.nodeName` / `children`(DeleteChild),確認後才帶 `-DryRun $false`(MCP:`DryRun=false`)。要刪除或大改前先問使用者。
4. **ConsumeXml 只送片段**:根元素 `<TreeItem>`,路徑照 ProduceXml 抄,只放要改的欄位,例如 `<TreeItem><TaskDef><CycleTime>40000</CycleTime></TaskDef></TreeItem>`(CycleTime 單位 100 ns)。不要整份 XML 回寫。
5. **看結果**:`data.verified=true` 才算成功;`data.backupPath`(`<solution 目錄>\.tcauto-backup\<時間>\`)和 `data.backupFiles` 是寫入前的備份,`data.warnings` 說明沒備份到的磁碟檔。`TREEITEM_VERIFY_FAILED` 不是成功。
6. TIPC 底下的修改會記 `BUILD_REQUIRED`(code-changed):Activate / Login 前要再完整 `Build-TcProject`。

## Testing Example

```powershell
$test1 = New-TcTestCase -Name "Initial state" -Assertions @(
    @{ Path = "MAIN.bReady"; Operator = "IsTrue"; Expected = $null }
    @{ Path = "MAIN.nCount"; Operator = "Equal"; Expected = [uint16]0 }
)

$test2 = New-TcTestCase -Name "Trigger and verify" `
    -Setup @( @{ Path = "MAIN.bStart"; Value = $true } ) `
    -WaitUntil @{ Path = "MAIN.bDone"; Operator = "IsTrue" } -WaitTimeoutMs 5000 `
    -Assertions @(
        @{ Path = "MAIN.bDone"; Operator = "IsTrue"; Expected = $null }
    ) `
    -Teardown @( @{ Path = "MAIN.bStart"; Value = $false } )

Invoke-TcTestCycle -TestCases @($test1, $test2)
```

Assertion / WaitUntil operators:`Equal`(預設)、`NotEqual`、`GreaterThan`、`LessThan`、`GreaterThanOrEqual`、`LessThanOrEqual`、`Contains`、`IsTrue`、`IsFalse`。`-WaitUntil` 的每個條件用同一組 key(`Path`、`Operator`、`Expected`),多個條件要在同一輪取樣(100 ms)同時成立;格式錯誤回 `INVALID_PARAMS`。MCP 呼叫 `NewTestCase`:`{"Name":"t","WaitUntil":[{"Path":"MAIN.bDone","Operator":"IsTrue"}],"WaitTimeoutMs":5000,"Assertions":[...]}`。

## Troubleshooting

| `IDE_BUSY` | XAE 被 modal dialog / license 視窗擋住,COM 回 RPC_E_CALL_REJECTED(0x80010001)或 RETRYLATER(0x8001010A);模組已重試 1/2/4/8/16s 仍失敗 | `Get-TcIdeModalDialog -ProcessId <data.ideProcessId>` 看是哪個視窗(reload-prompt → `Reset-TcSolution`),關掉 XAE 的 dialog,重跑同一個 cmdlet;不用重新 `Connect-TcIde`。`Connect-TcIde -SolutionPath` 回這個碼時沒有另開 IDE(#29) |

## 重要注意

1. **AmsNetId 是動態的**:不要寫死,從 `Connect-TcIde` 的 `data.amsNetId` 或 `Connect-TcAds` 自動偵測取得。
2. **Lifecycle 順序**:Build → `Enable-TcConfig -Force`(含 Login + PLC Run)→ `Connect-TcAds` → Read/Write/Test。port 851 只在 download 後存在。
3. **Activate 後不要重連 IDE**:原 COM 參考在 TwinCAT XAR 重啟後仍有效;ADS 則會自動重連(看 `reconnected`)。這是禁止的 fallback 之一(見「Failure contract」),`Invoke-TcTestCycle` 也不重連。
4. **測 FB 時寫 MAIN 層級變數**:PLC 每個 scan 都會覆寫 FB 的 `VAR_INPUT`,ADS 寫進去馬上被蓋掉;在 MAIN 宣告獨立變數餵給 FB。
5. **`Get/Write-TcPouCode` 的 `-PouPath` 可省略**:省略會自動找(`POUs` → project 根 → 遞迴搜尋),`data.pouPath`/`resolvedBy` 回報命中位置。4024 與 4026 格式相同:`TIPC^<PlcName>^<PlcName> Project^POUs^<PouName>`(DUT 在 `DUTs`、GVL 在 `GVLs`)。找不到看 `POU_NOT_FOUND` 的 hint 或 `Get-TcProjectTree -PlcOnly`。
6. **UmRT 0x502 / crash**:舊版曾回報「本機 UmRT 跑約 30 分鐘後 task 停止循環但 ADS 仍顯示 Run」,2026-11-08 實測未重現(跑 47 分,`_TaskInfo[1].CycleCount` 持續增加,#26);長時間測試想確認時讀 `TwinCAT_SystemInfoVarList._TaskInfo[1].CycleCount` 兩次。另有一種已實測到的:UmRT process 活著、CPU idle,對該 target 的每個 ADS 呼叫都回 **0x502「Mailbox is full」**(本機 TcSysSrv 正常),`Enable-TcConfig` 等 180 s 回 `SYSTEM_STATE_TIMEOUT`(2026-10-21);處置同樣是 kill 並重啟 `TcSystemServiceUm` 後 `Enable-TcConfig -Force`。UmRT 也會 crash(`TcOsSys.dll` c0000005,issue #21),同樣重啟 service。
7. **UmRT 的 Reset**:舊版說 `Set-TcPlcState -State Reset` 會結束 `TcSystemServiceUm`;2026-11-08 實測未重現(Reset 兩次,PLC 停在 Stop,service 同一個 pid 持續存在,再下 Run 恢復,#26)。需要重新載入程式用 Stop → `Enter-TcPlcOnline`;若 service 真的消失,走 `RUNTIME_CRASHED`。
8. **Build 失敗看 `data.errorItems`**:`Build-TcProject` 會用 UI Automation 讀 XAE Error List(`Get-TcBuildErrors`),每筆有 description/file/line;`code`(Cxxxx)是由描述推得,Error List 本身沒有 Code 欄,可能為 null。Build 成功時 `errorItems` 仍可能列出非 PLC code 的項目(例如 Library Manager 的「Could not open library '#System_VisuElem…'」placeholder 錯誤),這些列 `category = library`,只算進 `data.libraryErrors`;有這些列時 PLC 程式碼可能沒被編譯(4024 Festo 實測,#45),Build 回 `LIBRARY_UNRESOLVED` 而不是成功,先在 Library Manager 安裝缺的 lib。Warning 也有內容:`data.warningItems[]`(同格式)與 `data.codeWarnings[]`(排除 Library Manager 項),`warnings` 計數不再只是數字。注意 XAE 在 Build 前會自動存檔(Save all before build),`Write-TcPouCode` 後 Build 會寫到磁碟。不要盲目重跑 Build。
9. **重新 download 後舊 handle 失效**:不要快取 symbol 的 indexGroup/indexOffset 或 handle。download 前建立的 handle 回 ADS 0x711,沒有讀到別的變數(實測 2026-11-08,4026 VS2022 + 本機 UmRT,#26;這兩次 offset 沒變,offset 改變的情況沒測到)。`Read/Write-TcVariable` 每次重查 symbol,遇 0x711 自動重開 ADS session 重試一次並回 `data.symbolsReloaded = true`;程式是否換過看 `TwinCAT_SystemInfoVarList._AppInfo.AppTimestamp`。
10. **`error.hint` 有就照做**:它是模組對該 code 的建議下一步。經 MCP server 回傳時,hint 裡的 cmdlet 名已換成 tool 名(`Enter-TcPlcOnline` → `PlcLogin`、`Connect-TcIde -SolutionPath <sln>` → `ConnectIde SolutionPath=<sln>`)。
11. **直接改磁碟上的 .TcPOU / .plcproj 時**(不經 `Write-TcPouCode`):該檔**沒開**在 XAE 編輯器 → XAE 約 5 s 內自動重載、不跳框,改完等 5 s 再呼叫 DTE;該檔**開著** → 約 1 s 後跳 modal「File has been changed outside the environment. Reload the new file?」,所有 DTE 呼叫阻塞、VS 選項壓不掉,所以改完**立刻** `Reset-TcSolution`:它會先關掉這個提示(WM_CLOSE,`data.dismissedReloadPrompt`)、`Documents.CloseAll`(不存檔,`data.closedDocuments`;XAE 重開 solution 時會還原上次的編輯視窗,不關的話下次改磁碟又跳)、`Solution.Close`、在**同一個** IDE `Solution.Open` 再 `Connect-TcIde -SolutionPath`(solution-match 接回同 pid,`data.sameIde`),實測約 20~25 s。改寫 `.plcproj` 則跳「The project file ... has been modified outside of TwinCAT XAE. Do you want to reload the project?」(`reloadTarget = project`),同樣立刻 `Reset-TcSolution`:它對這個提示按 Yes(Win32 框依 control id、VS2022 WPF 框依 UIA Invoke,中文 UI 也行),XAE 自己 reload 專案,只重連不 close/reopen,比較快。改寫 `.sln` 跳的方案提示(`reloadTarget = solution`)它按忽略(1412)再 close/reopen。其他種類的 modal 它只回 `IDE_MODAL_DIALOG`。`Write-TcPouCode` 走 COM 寫進 IDE 的編輯 buffer(磁碟檔案的 mtime/hash **不變**,要到存檔或 Build 的 Save all 才落地),不會跳框,能用就優先用它;要讓磁碟同步就接著 `Build-TcProject`。
12. **MCP 同回合平行送的 tool call 到達順序不保證**:server 嚴格依到達順序一次執行一個,每個結果的 `order.seq`(遞增)、`order.startedAt`、`order.finishedAt` 告訴你實際順序(data 是物件時也在 `data.seq` 等;`GetSymbols`、多路徑 `ReadVariable` 的 data 是陣列,順序只在 `order`,#57);「寫參數 → 下命令 → 觀察」要分回合,等值用 `WatchVariable` 的 `Until`,不要用長 `DurationMs` 或連發 `ReadVariable`。
13. **先讓 solution platform 對齊 target 的平台**:target 支援 TARGETINFO 時 `Set-TcTarget` / `Enable-TcConfig` 自動對齊;這台的 UmRT 不支援(0x702),要 `Set-TcTarget -AmsNetId <id> -Platform 'TwinCAT OS (x64)'` 或 `Enable-TcConfig -Force -Platform 'TwinCAT OS (x64)'`(MCP:`RunLifecycle` / `SetTarget` / `EnableConfig` 的 `Platform`),再 Build + `Enable-TcConfig -Force`;只想換 NetId 用 `Set-TcTarget -NoPlatformSwitch`(不帶時讀不到 platform 會回 `PLATFORM_UNKNOWN`);否則 `ACTIVATE_FAILED`(Check config failed,target 上什麼都沒寫)。`SetTargetNetId` 不改 platform(實測);`Connect-TcIde` / `Get-TcIdeInfo` 的 `data.solutionPlatform` / `projectPlatform` 看現在是哪個。平台由目標對象決定,不看 XAE 版本;solution platform 名稱可能對到別的 project platform(Festo:`TwinCAT OS (x64)` → `TwinCAT OS (ARMT2)`),模組切換前檢查並回 `PLATFORM_PROJECT_MISMATCH`(`data.platformMap`):修 Configuration Manager,或專案不能改時照專案目前的平台用 `-NoPlatformSwitch`。
